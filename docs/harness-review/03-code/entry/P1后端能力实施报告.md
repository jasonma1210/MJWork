## 二、`judgeRoute` / `ruleRoute` 接口签名与路由类别语义

### 2.1 签名

```js
// main/entryRouter.js（CJS，零 electron 依赖，纯逻辑可单测）

/** @typedef {'simple_chat'|'multi_step_single'|'parallel_team'|'manual_team'|'scheduled'} RouteClass */

/**
 * @typedef {object} RouteVerdict
 * @property {RouteClass} route
 * @property {boolean} decidedByRule   true=规则层，false=模型层/兜底
 * @property {string}  reason          人话理由（写进 trace / 供 UI 解释「为什么这么走」）
 * @property {number}  confidence      0~1
 * @property {'rule'|'model'|'user'|'fallback'|'policy'} source
 * @property {object}  signals         {parallelizable, parallelHits[], sequential, sequentialHits[],
 *                                      needsCentralizedVerify, toolKinds, toolKindList[], estimatedSize,
 *                                      scheduledHint, manualTeamHint}
 */

/**
 * 规则层（纯函数、零成本）。判据是**任务结构**，不是长度/难度。
 * @param {string} goal
 * @param {{userPickedTeam?:boolean, chatOnly?:boolean, policy?:object}} [opts]
 * @returns {{verdict:RouteClass|'unknown', reason:string, signals:object, confidence:number, decidedByRule:true}}
 */
function ruleRoute(goal, opts = {}) {}

/**
 * 路由判定（异步）。L0 命中即返回；L0 判 unknown 才走 L1。
 * @param {{goal:string, userPickedTeam?:boolean, teamId?:string|null, chatOnly?:boolean,
 *          unattended?:boolean}} input
 * @param {{chatOnce?:Function, resolveModel?:Function, policy?:object}} deps
 *   policy 可传整份 entryPolicy.json，也可只传 new.autoDag 段
 * @returns {Promise<RouteVerdict>}
 */
async function judgeRoute(input, deps = {}) {}

/** 确认点判定（纯函数，不调模型、不建组） @returns {{tier:'C0'|'C1'|'C2'|'none', ask:boolean, blocked:boolean, reason:string, reasonSource:string, card:object|null, notice:object|null}} */
function decideConfirmPoint(verdict, ctx = {}) {}

/** 确认点 + 出卡前**预拆**（C1 时调 decomposeOnly） */
async function buildConfirmPoint(verdict, ctx = {}, deps = {}) {}

/** 只拆不建：拿子任务清单，不落库、不建组（复用 ORCHESTRATOR_SYSTEM + validateDag） */
async function decomposeOnly(goal, deps = {}) {}   // → {ok, tasks?, error?}

/** 纪律②：记录/查询「本目标已被用户答复」 */
function noteUserChoice(sessionKey, goal, choice /* 'single'|'confirm' */) {}
function hasAnswered(sessionKey, goal) {}
```

### 2.2 路由类别语义（离散，不用难度分）

| 类别 | 含义 | 执行路径 |
|---|---|---|
| `simple_chat` | 单 Agent 对话 | 现有 `agent-core.runAgent` 直连 |
| `multi_step_single` | 单 Agent 多步（要拆但不需要并行） | 复用既有 `looksLargeTask` → `decomposeTask` → 拆分卡片 |
| `parallel_team` | 可真正并行分解 ⇒ 可升级为团队 | 模型调 `orchestrate_task` / 用户点确认卡 → `teams:dispatch` |
| `manual_team` | 适合组队但需人工编排 | **不自动建组**，只引导去助理页 |
| `scheduled` | 应做成定时任务 | **不自动创建**，只引导去助理页定时任务视图 |

### 2.3 L0 规则层的判定顺序（每步都给「命中 ⇒ 直接返回」）

| 序 | 条件 | 结果 | 理由（人话，进 `reason`） |
|---|---|---|---|
| 1 | `opts.chatOnly` | `simple_chat` | 对话型目标 |
| 2 | `opts.userPickedTeam` | `parallel_team` | 用户已明确选编制 |
| 3 | 命中 `scheduledPatterns` | `scheduled` | 含定时特征 |
| 4 | 命中 `manualTeamPatterns` | `manual_team` | 要人工组队 |
| 5 | 命中 `sequentialPatterns` | `multi_step_single` | **强顺序依赖 ⇒ 禁止升级** |
| 6 | `toolKinds ≥ toolKindThreshold(16)` | `multi_step_single` | 工具面太宽，多 Agent 开销大于收益 |
| 7 | 命中 `parallelizablePatterns` | `parallel_team`（高置信 0.85 / 中档 0.6） | 各部分互不依赖，可并行 |
| 8 | 命中 `centralizedVerifyPatterns` 但无并行信号 | `multi_step_single` | 要汇总但不必并行 |
| 9 | 都不命中 | `unknown`（→ L1） | 规则层判不准 |

> 「可并行 / 顺序依赖」**全部是启发式**（模式串在 `entryPolicy.json`），**不调模型**；L1 只在第 9 步之后才被调用。

### 2.4 L1 模型层

- 一次短调用（`timeoutMs=15000`、`maxIn=1500 / maxOut=200`、`temperature=0`），输出严格 JSON `{"route":<离散类别>,"reason":"...","confidence":0..1}`。
- **失败 / 超时 / 输出非法 / 类别不在枚举 / 置信度 < 0.6 ⇒ 一律降级 `simple_chat`（source='fallback'）**。
- 规则层已能判定时**绝不调模型**（门禁断言调用次数 = 0）。

## 三、确认点三档（C0 / C1 / C2）判定条件表

### 3.1 判定顺序（`decideConfirmPoint`，纯函数）

| 序 | 条件 | 档 | `ask` | `blocked` | 用户看到 |
|---|---|---|---|---|---|
| 0 | `ctx.unattended && route==='parallel_team' && !ctx.scheduledTeamId` | `none` | false | **true** | **不升级**（纪律③） |
| 0' | `ctx.unattended` 其余情形 | `none` | false | false | 无确认点，按预声明执行 |
| 1 | `route ∈ {manual_team, scheduled}` | **C2** | false | **true** | 引导按钮（去助理页组建 / 创建定时任务） |
| 2 | `route ∈ {simple_chat, multi_step_single}` | **C0** | false | false | 无（若因顺序依赖/工具密度降级，附降级提示） |
| 3 | `parallel_team && ctx.userPickedTeam` | **C0** | false | false | 事后提示「已按团队执行 · N 倍 token」 |
| 4 | `parallel_team && 高置信 &&（用户开自动升级）` | **C0** | false | false | 同上 |
| 5 | `parallel_team && 高置信`（confidence ≥ 0.75 且 toolKinds ≤ 8 且 teamSize ≤ 3 且无顺序依赖） | **C0** | false | false | 同上 |
| 6 | 其余 `parallel_team`（中置信 / 工具 8~16 / 规模 4~5 / 需交叉核对） | **C1（默认档）** | **true** | false | 确认卡（含**已拆好**的子任务 + 代价 + 三个动作） |

### 3.2 三条纪律的代码落点

| 纪律 | 落点 |
|---|---|
| ① 确认卡里的子任务必须是**已拆好**的 | `buildConfirmPoint` 在 tier==='C1' 时先调 `decomposeOnly`（纯拆解：复用 `ORCHESTRATOR_SYSTEM` + `validateDag`，**不调 planGoal** ⇒ 不建组、不落库），把结果填进 `card.subtasks` 并置 `subtasksReady`。拆不出来时 `subtasksReady=false` + `subtaskError`，**不假装拆好了**。用户点「按这个执行」后，`teams:dispatch` 的**可选** `presetTasks` 让编排器直接用这份清单（跳过 LLM 重新拆解） |
| ② 「改成单 Agent」⇒ 不升级且不重复追问 | `noteUserChoice(sessionKey, goal, 'single')` 记录（目标指纹 = 去空白 + 截 200 字）；`judgeAndStart` 每轮先查 `hasAnswered`，命中则直接广播 downgrade 事件并**不判定、不追问** |
| ③ 无人值守无确认点、不得静默升级 | `decideConfirmPoint` 的序 0：`unattended && parallel_team && !scheduledTeamId` ⇒ `blocked=true`，reason 明写「须预先声明 team_id 与预算」。定时通道本身只认任务上已落库的 `team_id`（`scheduledTeam.prepareScheduledRun` fail-closed） |

## 四、UI 事件契约（给渲染层成员的联调契约）

> **两条事件都走 `webContents.send` 广播到所有窗口**（与 `teams:event` / `tasks:event` 同款）。
> **不进 system prompt**（system 是前缀稳定区，加内容会让每轮重写前缀，拖垮 prompt cache）。

### 4.1 `entry:route` —— 判定结果 + 升级/降级提示 + 成本倍数

```js
{
  type: 'route_verdict' | 'upgrade' | 'downgrade' | 'guide',
  conversationId: string|null,
  route: 'simple_chat'|'multi_step_single'|'parallel_team'|'manual_team'|'scheduled',
  decidedByRule: boolean,
  source: 'rule'|'model'|'user'|'fallback'|'policy',
  confidence: number,            // 0~1
  reason: string,                 // 人话理由（可直接展示）
  tier: 'C0'|'C1'|'C2'|'none',    // 确认档
  ask: boolean,                   // 是否需要用户确认（仅 C1 为 true）
  blocked: boolean,               // C2 / 无人值守越界 为 true
  reasonSource: string,           // 'rule-high-confidence'|'medium-confidence'|'user-picked'|'auto-upgrade'|'route-class'|'single-agent'|'unattended-guard'|'user-choice'|...
  signals: {
    parallelizable: boolean, sequential: boolean,
    toolKinds: number, needsCentralizedVerify: boolean, estimatedSize: number,
  },
  notice: { type:'upgrade'|'downgrade', route:string, teamSize:number, tokenMultiple:number } | null,
  cost: { teamSize:number, tokenMultiple:number, estimatedWallClockMs:number } | null,
  team: { id:string, name:string|null } | null,   // payload.teamId 存在时回填
  ts: number,
}
```

**渲染建议**：`notice.type==='upgrade'` ⇒ 显示「已升级为 N 人团队执行 · token 约 N 倍」（`costNotice`/`showUpgradeNotice` 开关在 policy）；`'downgrade'` ⇒ 「已按单 Agent 执行」；`type==='guide'` ⇒ 按 `tier==='C2'` 显示跳转按钮（`card.guideAction` = `open_assistant_team` / `open_assistant_scheduled`，见 4.2 的 card）。

### 4.2 `entry:confirm` —— C1 确认卡（仅 `tier==='C1'` 时发）

```js
{
  type: 'confirm_card',
  conversationId: string|null,
  goal: string,
  route: 'parallel_team',
  card: {
    title: string,                 // 「建议用 N 人团队执行此任务」
    reason: string,                // 一句人话理由
    reasonSource: string,
    subtasks: [ { id:string, title:string, dependsOn:string[] } ],  // ★ 已拆好（不是「打算怎么拆」）
    subtasksReady: boolean,        // false ⇒ 拆解失败，UI 必须显著提示
    subtaskError: string|null,
    signals: { parallelizable, sequential, toolKinds, needsCentralizedVerify },
    conservative: boolean,         // true ⇒ 工具种类 ≥16，建议单 Agent / 只读子代理
    conservativeHint: string,
    cost: { teamSize:number, tokenMultiple:number, estimatedWallClockMs:number },
    actions: ['confirm','single','detail'],
    // C2 引导卡会额外带：guideAction: 'open_assistant_team'|'open_assistant_scheduled'，guide:{action,label}
  },
  ts: number,
}
```

### 4.3 渲染层 → 主进程：`entry:choice`（新增 IPC，preload 桥 `entryChoice`）

```js
api.entryChoice({ conversationId, goal, choice: 'single' | 'confirm' })
// → { ok: boolean }
```
- `'single'` ⇒ 本轮不升级，**且同一会话同一目标不再追问**（主进程记内存态，重启即清）。
- `'confirm'` ⇒ 记为已答复（同样不再追问）；真正建组请调**既有** `api.teamsDispatch({ teamId, goal, threadId, presetTasks: card.subtasks })`。

### 4.4 `entry:policy`（IPC，preload 桥 `entryPolicy`）
`{ ok:true, policy: <entryPolicy.json 全文> }` —— 渲染层不要复制一份阈值。

### 5.2 响应

```js
{
  ok: true,
  draft: {
    name: string,                      // ≤40 字
    description: string,               // ≤200 字
    requiredCapabilities: string[],    // 模型判定本需求真正需要的能力键（枚举：read/write/execute/search/web/browser/plan）
    members: MemberDraft[],
```

### 5.3 `MemberDraft`（真实返回结构，**七条字段来自下方实测**）

| 字段 | 类型 | 来源 | 说明 |
|---|---|---|---|
| `name` | string | 目录模板标题 / 模型 | ≤40（`MEMBER_NAME_MAX`） |
| `systemPrompt` | string | 目录模板 || 模型 | 目录成员**用模板原文**（模型不得改写） |
| `tools` | string[] | 目录 `emp.tools` 白名单过滤 || 模型 | **抽象别名**（read/write/edit/bash/grep/glob/web/browser），非法别名已丢弃 |
| `toolNames` | string[] | `normalizeMemberInput` 映射 | **引擎具体工具名**（read_file/shell/...），落库与运行期都用它 |
| `approvalMode` / `approvalPolicy` | string | 枚举归一 | 同值双字段：`approvalMode` 是落库字段名，`approvalPolicy` 是设计文档 §8.2 的字段名。非法值 ⇒ `on-request` |
| `sandboxPolicy` | string | 枚举归一 | `read-only`/`workspace-write`/`full-access`，非法 ⇒ `workspace-write` |
| `skillNames` | string[] | 目录 `starter_skills` || 模型 | |
| `source` | `'template' \| 'custom'` | 目录命中 ⇒ `template` | ⚠️ **偏离任务书 `source:'employee'` 的原因见 §九-1** |

| `matchScore` | number \| null | 确定性计算 | 目录成员有值 `(0,1]`；自由生成成员为 `null` |

| `roleKind` | `'lead' \| 'member'` | 模型标注 | 恰好一名 `lead`（统筹） |
| `role` | string | 模型 | 这个成员负责什么（≤200） |

### 5.4 `CoverageReport`

```js
{
  covered: string[],   // 已覆盖的能力键（read/write/execute/search/web/browser/plan）
  missing: string[],   // 缺失的能力键
  warnings: string[],  // 人话提示，例：「需求提到「联网查证」，但草案里没有成员被授予 web 工具。」
                       //              「目录里没有 id 为 X 的数字员工，该成员已从草案中移除。」
  sufficient: boolean, // missing.length === 0
}
```
- **能力覆盖是确定性判定**：`policy.assistant.aiTeamDraft.capabilityToolAliases` 把能力键映射到抽象别名；`plan` 由「草案里有统筹（roleKind='lead'）」覆盖（`planCoveredByLead`）。
- `matchScore = round(0.7 × 能力覆盖率 + 0.3 × 模型自报 fit, 3)`；无 `fit` 时 = 覆盖率。

### 5.5 三条安全语义（已由门禁断言）

1. **只出草稿不落库**：`teamsDraft.js` 不 require 任何 store；门禁用真 SQLite 断言「调用前后 `team_members` 行数不变」。
2. **目录优先**：命中目录 ⇒ `source='template'` + `templateRef` + 目录原文提示词；`templateRef` 不存在 ⇒ **该成员被移除并留告警**（fail-closed，不凭空造成员）。
3. **非法值一律 fail-closed**：工具别名只留 `ROLE_TOOL_ALIASES` 的键；审批/沙箱档非法 ⇒ 回落最保守档；归一化复用既有 `normalizeMemberInput`（未另写一份）。
