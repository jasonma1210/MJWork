#### D-1（缺陷级）`teams:dispatch` 把归一结果覆盖成 raw 清单

`main/ipc/teams.js` 的 `teams:dispatch` handler 里：

```js
const presetTasks = chatOnly ? buildChatTasks({ roster }) : normalizePresetTasks(payload.presetTasks);
...
const confirmedTasks = Array.isArray(payload.presetTasks) ? payload.presetTasks : null;
const planOpts = {
  ...
  ...(presetTasks    ? { presetTasks }                : {}),
  ...(confirmedTasks ? { presetTasks: confirmedTasks } : {}),   // ← 后者覆盖前者（raw 未归一）
};
```

对象展开后出现的同名键会**后写的赢**，因此只要 `payload.presetTasks` 是数组，进入 `planGoal` 的就是**渲染层原样回传的 raw 数组**。

实证（同一份清单，两种走法）：把含 `ghost` 依赖 + 自环的清单**直接**喂 `planGoal` → `THREW: Cannot read properties of undefined (reading 'dependsOn')`；先过 `teamDispatchPlan.normalizePresetTasks` 再喂 → `ok:true`（归一后 `dependsOn` 被剔成 `["t1"]` / `[]`）。

后果三条：
1. `main/teamDispatchPlan.js` 的 `normalizePresetTasks`（8 条封顶 / 缺 id 补号 / 依赖存在性剔除 / 自环剔除 / 超长截断）**在本轮生产路径上输出被丢弃**，只剩测试在消费它 ⇒ 事实上是「写了但没接上」的形态。
2. 实际生效的是 `main/orchestrator/index.js` 内另一份私有 `normalizePresetTasks`——它只做「prompt 必填 + id 去重/补号 + `MAX_TASKS` 截断」，**不校验依赖存在性、不剔自环**。坏依赖因此直达 `topoLevels`（`main/orchestrator/dag.js` 的 `memo`），抛 TypeError 被外层 catch 成 `DISPATCH_FAILED`；自环则静默落库（⑤）。
3. handler 里「不合法则回落 LLM 拆解」的注释承诺**不成立**：②/③ 实测是硬失败，既不回落也不降级。⑦ 还显示对话型确定性旁路（`buildChatTasks`）会被不可信的 IPC 入参覆盖。

严重度定为**缺陷（非阻断）**，理由：正常 UI 路径不会触发——`entryRouteView.dispatchPlanOf` 会用 `title` 兜底补齐 `prompt`，依赖又来自 `entryRouter.decomposeOnly` 内已过 `validateDag` 的清单。但只要有任何一方（渲染层回归、第三方调用方、未来新入口）直接回传未经校验的清单，就会从「降级」变成「整次派活失败」。
