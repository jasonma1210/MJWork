## 四、发现项明细

### P1 · 所有 `textarea` 键盘焦点环被抹除（可访问性缺陷）

**根因链**

1. `theme.css:335` 注释声明意图：`/* C9：全局键盘焦点可见性 */`；
2. `theme.css:336-338` 提供兜底：`:focus-visible { outline: 2px solid var(--sem-focus); outline-offset: 1px; }`；
3. 但 `theme.css:430` 存在 `textarea:focus { outline: none; }`；
4. **CSS 特异性**：`textarea:focus` = (0,1,1) **高于** `:focus-visible` = (0,1,0)，故该规则**无条件覆盖**全局焦点环——包括键盘焦点；
5. 多数 textarea 自身**无补偿焦点样式** → 键盘 Tab 到输入框时**无任何视觉反馈**。

**证据：含 `textarea` 且文件内 focus 类数为 0（确定无焦点环）**

| 文件 | 说明 | 文件内 focus 类数 |
|---|---|---|
| `Composer.tsx` | **主聊天输入框**（最高频交互） | **0** |
| `desk/DeskIntake.tsx` | 工作台接单输入框 | **0** |
| `TeamsPage.tsx` | 团队页 | **0** |
| `TeamMemberModal.tsx` | 成员编辑弹窗 | **0** |
| `RecordReplayPanel.tsx` | 录制回放面板 | **0** |

另有 8 个含 textarea 的文件**文件内存在 focus 类**（`Input.tsx`2、`LocalMcpSection`5、`CustomConnectorForm`2、`DiffReviewPanel`4、`PublishTaskPage`1、`AiTeamBuilder`1、`ApprovalCard`1、`ScheduledTasks`11）——但那是**文件级计数**，是否恰好作用于 textarea 需逐处确认，故此处不列入确定受害清单（属「待逐处核实」）。

**影响**：键盘用户（含无障碍使用者）在**主输入框**无法感知焦点位置，违反该文件自身声明的 C9 意图。

**修复方案（最小一行）**

```css
/* theme.css:430 —— 仅去掉鼠标点击的默认环，保留键盘焦点环 */
textarea:focus:not(:focus-visible) { outline: none; }
```

- 更彻底方案：直接删除 `theme.css:430` 整行，让全局 `:focus-visible` 全权生效。
- 风险：极低（仅影响 textarea 的焦点轮廓；`:focus-visible` 在鼠标点击时不触发，观感不变）。
- **代价**：1 行 CSS，无组件改动，无 i18n 改动。

### P2 · 工作台「最近运行」卡恒为死 UI（仪表盘占位浪费）

**根因链**

1. `DeskPage.tsx:215` 无条件渲染 `<DeskRunsCard variant="recent" />`，**不传任何 props**（无 `threadId`、无 `projectPath`）；
2. `DeskRunsCard.tsx:76-83` 的 `variant === 'recent'` 分支**直接 return 静态文案** `t('desk.runs.empty')`，**不取数、无任何数据依赖**；
3. `zh-CN/desk.json:74` 该文案为「尚未接线：本机不提供跨会话的运行记录」；
4. 结论：该卡**永远显示同一句占位文案**，是仪表盘上的**永久死 UI**。

**关键矛盾（数据其实可得）**

- 同一份 `tasksList({ limit: 30 })`（→ `taskStore.listGroups`）**已按 `created_at DESC` 返回全部近期任务组**，含 `done`/`failed`/`cancelled` 等终态；
- 即：**本会话的「最近运行」真实数据已经在那次调用里返回了**，只是 recent 分支没用（取数逻辑只在 `variant === 'running'` 分支执行）。

**影响**：用户刚明确「工作台应是 dashboard，含使用量/任务进度等」，而该卡恒定无信息，占掉一屏有效区域。

**修复方案（二选一，需定语义边界）**

| 方案 | 做法 | 优点 | 代价/风险 |
|---|---|---|---|
| **A（保守·最小）** | 未接线前**整卡卸载**，不留死 UI | 零假数据、零语义争议、改 1 处 | 该屏少一块内容 |
| **B（推荐·需确认）** | 给 recent 变体接 `threadId`/`projectPath`，复用同一次 `tasksList` 取**非 running** 的近期组渲染 | 真实数据、补齐 dashboard 内容 | 需确认「最近运行」是否限定**本会话**（跨会话仍无源）；需新增 i18n 键与终态展示样式 |

> 语义边界待确认项：注释称「没有跨会话运行记录的数据源（`runRegistry` 是模块级 Map，刷新即空）」——**跨会话**确实仍无源；但**本会话**近期组可由 `listGroups` 提供。若采纳 B，应明确文案口径为「本会话最近运行」，不得宣称跨会话。

### P3 · 10 处任意值字号绕过排版 token

**证据清单**

| 值 | 落点 | 处数 |
|---|---|---|
| `text-[11px]` | `TeamDebugPanel.tsx:174,197,207,211,222,225` | 6 |
| `text-[11px]` | `EcosystemModal.jsx:511`、`MermaidDiagram.tsx:79`、`Composer.tsx:238` | 3 |
| `text-[15px]` | `TopBarTitle.tsx:36` | 1 |

**对照排版 token**（`tailwind.config.js:63-70`）

| 语义类 | 字号 | 行高 |
|---|---|---|
| `text-caption` | **11px** | 16px |
| `text-code` | 12px | 18px |
| `text-xs` | 13px | 20px |
| `text-sm` | 14px | 21px |

- 9 处 `text-[11px]` **恰有 `text-caption`(11px) 对应** → 应替换（收益：字号与行高成对受 token 管控，主题可统一调整）；
- `text-[15px]`（TopBarTitle 的视图标题）**在排版档中无对应 token**（档位为 11/12/13/14，默认 base=16）→ 属**离档值**，建议归到 `text-sm`(14) 或补一枚标题 token。

**修复方案**

```diff
- text-[11px]
+ text-caption        // 9 处，语义等价（11px），并引入配套行高 16px
```

- **行高注意**：`text-caption` 自带 `lineHeight:16px`；原处若已写 `leading-snug`/`leading-relaxed`，Tailwind 中 `leading-*` 生成序在 `fontSize` 之后，**会覆盖** caption 行高 → 原观感不变；原处若**未写** leading，则行高由浏览器默认变为 16px，需目测确认无跳动。
- 建议：替换后逐处核对这 9 处是否存在显式 `leading-*`（已知 `TeamDebugPanel:197` 与 `Composer:238` 带 `leading-snug`，`:225` 带 `leading-snug`）。
- 风险：低（字号数值完全等价）；代价：9+1 处纯替换，无逻辑改动。
