## 3. 账本（ledger）：数据源只够支撑 1/5 到的板块

| 原型板块 | 数据源 | 证据 |
|---|---|---|
| 周期支出 **¥** / 运行次数 / Token | ⚠ 只有后两项 | `quota_consumptions` 只有 `tokens`；**全 main 无价格表**（grep `price\|pricing\|cost_usd\|usd` 零命中） |
| 每日花费柱状图 | ✗ | 无按日聚合 IPC，且无金额 |
| 项目分摊 | ⚠ | 有 `project_id`，但只暴露**单项目当前窗口水位**（`projects:quota`），无跨项目/跨区间聚合 |
| 成员分摊 | ⚠ | 有 `member_id` 且 `quotaLedger.memberUsed()` 存在，**但没接任何 IPC** |
| 配额桶 | ✓ | `quota_buckets`；注意单位是 **token**（默认上限 3,000,000），不是原型表格里的"¥ 已用/¥ 上限" |
| 结算单 | ✗ | 全仓无 settlement 概念 |
| 结算规则（70%/90%/100% 提醒） | ✓ 概念有 | `warn_ratio 0.7` / `throttle_ratio 0.9` |

> **结论**：账本页照原型做 = **4/7 板块要造假数据**。真要做，只能先做"token 口径的用量页"，并明确标注"本地不折算金额"。
> 另注：`quota:snapshot` **不是**钱账本，是并发槽位 `ResourceQuotaCenter`（`main/main.js:265-268`），别误用。

## 4. 设计 token 差异：7 个危险项

| # | 项 | 原型 | 现有 | 危险度 |
|---|---|---|---|---|
| 1 | **`--shadow-pop`（完全同名）** | 暖黑 `rgba(20,20,18,.16)` | 纯黑 `rgba(0,0,0,.22)` | **高**：同名 + 不同色相基，直接覆盖影响所有 popover |
| 2 | 主色角色 | `#2E4B3C` 暗墨绿 | `#12b48c` 亮青绿，且现有有 **5 套主题 × 6 种自选强调色**（含 `#3B82F6` 蓝、`#8B5CF6` 紫） | **极高**：与原型"绝不出现蓝"直接冲突 |
| 3 | 默认明暗 | 写死 `data-theme="light"`（纸白） | `:root` 就是**暗色**，首启跟随系统 | **极高**："看起来只改颜色、实际换了个产品" |
| 4 | 浅色底 | `--paper #F3F3EF`（暖纸白） | light `#ffffff`（纯白），且 `--paper-2` 无对应物 | 高：整站色温变化 |
| 5 | 圆角档位 | r-1=8 / r-2=10 / r-3=14 | sm=6 / md=8 / lg=10 / xl=14 | 中：**错位一档**，逐值替换会整体缩一号 |
| 6 | `--fill-1/2/3` 3 档透明填充 | 3 档 | 只有 `--theme-hover` 1 档 | 中：侧栏 hover 与选中态只能二选一 |
| 7 | 字体 | **serif** / sans / mono | 只有 mono，**全仓 `font-serif` 零命中** | 低（纯收益） |

**纯收益项**（建议做，风险接近 0）：`--ease-out cubic-bezier(.16,1,.3,1)`（现有没有，比 `--ease-standard` 更适合大位移转场）；`--font-serif`（原型的衬线标题是最强的观感来源之一）。

## 5. 需要你拍板的三个决策

### 决策 1：设置页要不要从弹层改成一级页面？

- **原型做法**：一级页面
- **建议：保留弹层，不改成页面。** 三条理由：
  1. 丢掉"任意会话里 ⌘, 叠一层、改完就关"的回路，而设置 60% 的用途是"改一下马上回来"
  2. `settings-coverage.test.js:101,103` **硬绑浮窗形态**（断言 `fixed inset-0 z-settings` + `rounded-2xl shadow-[var(--shadow-modal)]` + `onClick={onClose}` 恰好 1 处），改页面要动测试契约
  3. 原型设置页的价值 90% 来自**信息架构**（左分组导航 + 搜索 + 快捷键提示），与"是不是弹层"无关；而现有弹层内**已经是**左导航 + 右正文
- **折中**：保留弹层，只补原型的三样结构件：`恢复默认`按钮、`侧栏默认折叠`开关、左导航分组标签（现有已有分组，够用）

### 决策 2：账本要不要做？做到什么口径？

- **原型做法**：¥ 金额账本（含结算单、每日花费图）
- **建议：不做"账本"，先做"用量"页（token 口径）**，四块：周期用量 / 项目分摊 / 成员分摊 / 配额桶。**不要用 ¥ 符号**。
- 若你要真账本，前置条件是：① 补一张模型价格表 ② 新增聚合 IPC ③ 补成员级 IPC ④ 想清楚"本地优先、用户自带 Key"下金额怎么算（用户自己的 Key 计费在服务商后台，本地算不出来）
- **这条我建议你明确一下**：你是想要"看花了多少钱"，还是"看用了多少额度"？前者在这个产品形态下**本地算不出来**。

### 决策 3：主色与默认明暗要不要对齐原型？

- **原型**：暗墨绿 `#2E4B3C` + 纸白底
- **现有**：亮青绿 `#12b48c` + 暗色底（首启跟随系统）+ 6 种自选强调色
- **建议：先不动色相与默认明暗**，只对齐层级/圆角/字号/衬线这四项 —— 这三项对齐后观感已接近 80%，而风险接近 0。理由：
  - 换色 = 4 个主题 + 6 种强调色全改，且与"用户可自选强调色"的产品能力冲突
  - 改默认明暗 = 首屏观感全变，用户第一眼会以为换了产品
- 若你确实要改，建议单独一批做，且保留"用户自选"能力

## 7. 三条会咬人的门禁（照搬 HTML 必撞）

| 门禁 | 约束 |
|---|---|
| `ui-conventions` `rawButton: 255` **只降不升** | 原型全是裸 `<button>`（desk 一屏 20+ 个）。新页面必须全部走 `components/ui/Button.tsx`（6 种 variant / xs·sm·md） |
| `i18n-scan` 禁裸中文 + `i18n-modcheck` 双侧键集一致 | 原型 0 处 i18n。每句可见文案都要进 `zh-CN/*.json` **和** `en-US/*.json`（现有 42 模块）。建议新页面各建一个模块（`desk.json`/`studio.json`/`usage.json`） |
| `no-new-jsx` | `renderer/src` 下**新增** `.js/.jsx` 一律拒绝，必须 `.ts/.tsx`；且基线里的文件必须仍存在——**不能靠删文件"减基线"**，迁移要同步删基线项 |

## 8. 不建议照搬的 9 处（含折中）

1. **设置弹层改页面** —— 见 §5 决策 1，建议不做
2. **账本整页照搬** —— 会造假数据，见 §3
3. **`--ease-spring` 弹跳曲线** —— 现有明令"禁弹跳曲线"（`theme.css:254`）+ `prefers-reduced-motion` 全局降级。只取 `--ease-out`
4. **主色换暗墨绿 + 去蓝紫** —— 与"用户自选强调色"冲突，见 §5 决策 3
5. **侧栏苔绿滑动指示块**（JS `getBoundingClientRect` 测量 + 弹跳过渡）—— 与现有选中态功能重复，且 JS 测量在折叠动画/滚动/缩放时会错位。保留现有 `aria-current + select-bg`
6. **侧栏底部"本月已用 ¥12,480 / 预算"** —— 无金额源，且把成本常驻前置会持续给压力
7. **"早上好，老板" + 硬编码日期** —— 原型是静态稿，做的时候必须 `new Date()` + i18n 日期格式
8. **sheet 拖拽关闭**（`pointerdown/move/up` + 120px 阈值）—— 现有 `ui/Modal.tsx` 是 W3C Dialog 模式（焦点陷阱 + 栈 + Esc），再加 pointer 拖拽会成为**第二条关闭路径**，需同步 `modal-keyboard-guard` 测试。桌面端拖拽关闭是移动端手势遗产
9. **`view-max: 1280px` 内容居中** —— 现有全宽；三栏 + 右栏面板时可用宽度本就不足。折中：只给新页面（desk/用量）加，不动 ChatArea 系
