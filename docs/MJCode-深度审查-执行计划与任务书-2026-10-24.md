## 2. 关键方法修正（不修这一条，计划会变成第十轮「更大」的审查）

原始 8 条 P0、5 条 P1 不能套同一种证法。必须先分类，否则会出现「用叙述冒充反事实」。

| 类型 | 特征 | 只能用哪种证法 | 涉及条目 |
|---|---|---|---|
| **A 已实现但未接通** | 代码在、调用链断、行为不可见 | **反事实**：接通前后各测一次，红→绿 | P0-2 工件→产物桥、P0-4 团队无人值守、P1 超时信号 RPC 丢失、P1 截图模型不可见 |
| **B 已实现但语义错** | 行为存在、方向不对 | **反事实**：改对后旧断言红、新断言绿；若旧断言也绿 ⇒ 该断言把缺陷固化 | P0-1 沙箱默认档、P0-5 一成员失败整组失败、P0-7 首聊无模型、P0-8 docx 框线 |
| **C 完全没做** | 代码里没有这条路径 | **存在性否证**：给出「全仓零调用点/零符号」的检索输出；禁止只说「没有」 | P0-3 读回 Office、P0-6 签名与 notarize、P1 无 Anthropic 协议、`rebuildVersion` 零调用方 |
| **D 判定链本身** | 门禁放过了上面三类 | **变异**：注入 → 期望红 → 实测 | W1 全部 |

**红线**：C 类条目**不得**写「反事实实验」章节——没有实现就没有红绿。写了就是伪造。

### T-01 冻结与基线

- **目标**：让「当前状态」这个词有一个可复跑的指向。
- **前置**：无。
- **输入**：仓库根 `/Users/jianma/Desktop/MJCode`；`desktop/package.json` 的 `test` 脚本。
- **步骤**：
  1. `git status --short` 全量记录；把文档类未提交项（`deliverables/`、`docs/patches/`、两份 10-24 文档、`.wiki-creator/wiki/.manifest.json`）分一次提交，提交信息写「docs: 审查题目与计划」。
  2. 提交后记 `git rev-parse HEAD`（全 SHA）与 `git status --short` 结果（应为空）。
  3. `git worktree add /tmp/mjcode-wt <SHA>`。
  4. 软链 `node_modules`：仓库根与 `desktop/node_modules` 两端。
  5. `cd /tmp/mjcode-wt/desktop && NODE_OPTIONS=--preserve-symlinks npm test > /tmp/w0-baseline.txt 2>&1`。
  6. 取 4 个数字（总/过/败/跳）与耗时；确认无活跃写入者、机器空载。
- **验收**：① `00-baseline/基线快照.md` 里出现完整 SHA、四数字、命令原文、执行时间；② 同一命令再跑一次，四数字一致；③ `git status` 在 worktree 内为空。
- **产出**：`00-baseline/基线快照.md`、`/tmp/w0-baseline.txt`。
- **边界**：禁止在此步骤修任何代码；禁止用工作区读数替代 worktree 读数。
- **失败处理**：软链后出现 `ipcMain undefined` 类假红 ⇒ 检查是否漏了 `NODE_OPTIONS=--preserve-symlinks`（缺它会因 Node 解析真实路径让 electron 打桩失效）。

### T-02 源码形态断言普查（假闸的候选池）

- **目标**：把所有「不执行行为、只读源码文本」的断言找全，形成候选池。这是 W1 的入口，不做普查就逐个瞎试。
- **前置**：T-01。
- **输入**：`desktop/test/*.test.*`（现算 286 个文件）。
- **步骤**：
  1. `rg -l "readFileSync|readCode|read\(" desktop/test > /tmp/w1-files.txt`。
  2. 逐个文件判定三件事：断言的是**行为**（调用函数/接口）、**结构**（文件存在、导出名）、还是**源码文本**（`includes` / 正则匹配代码）。
  3. 对「源码文本」类，标注：是否 `stripComments` 过；同文件是否有对应行为断言（如 `memory-file-channel` 的 D0 组）。
  4. 排序：无行为对照 + 未剥注释 = 高危候选。
- **验收**：① 表格行数 == 普查到的源码文本断言条数（不是文件数）；② 每条带 `文件:行`；③ 人工抽 3 条回读源码，行号与判定一致；④ 高危候选 ≥1 条时，必须进入 T-03~T-05 的变异清单。
- **产出**：`01-gates/假闸清单-v2.md`（候选池 + 判定 + 排序）。
- **边界**：只读断言，不改门禁代码；发现门禁写得差也不在本任务修。
- **失败处理**：若 `rg` 命中为空，先用 Grep 工具复核（macOS 的 `grep` 是 BRE，`\|` 恒不生效，会给出假阴性）。

### T-06 反事实组 A：接线类（A 类问题）

- **目标**：给「已实现但未接通」的每条问题一个红→绿证据。
- **前置**：T-01。
- **输入**：`main/docTools.js`、`agent-core/index.js`（工具面）、`main/scheduledTools.js`、`main/main.js`、`childEntry.js`/`host.js`、`main/browserTools.js`。
- **覆盖条目（每条独立一节）**：
  1. **P0-2 工件→产物桥**：`doc_create` 等四个工具参数里无 `artifactId`（证据 `main/docTools.js:163-195`）。实验：给工具加 `artifactId` 入参 → 由工件渲染 docx → 断言 docx 内容 == 工件内容（字节级或文本级），且 token 侧不再全文回传。
  2. **P0-4 团队无人值守**：`main/scheduledTools.js:98-104` 无 `team_*` 注入。实验：定时上下文构造一次派活，断言 `teamTools` 存在且 roster 可读；再断言成员产出落库。
  3. **P1 超时信号跨 RPC 丢失**：`childEntry.js:58`、`host.js:97` 只搬 `args`。实验：注入一个 `sleep 5s` 工具 + 1s 超时，断言子进程被杀（而不是继续跑）。
  4. **P1 截图模型不可见**：`browserTools.js:170-197` 只回 `{path,bytes,previewUrl}`。实验：截图后模型侧可见内容（图像块或 OCR 文本）存在；`read_file` 读图不再返回乱码。
- **验收（每条）**：① 有「修复前」实测（失败/缺失的具体输出）；② 有「修复后」实测（通过输出）；③ 两步命令可复跑；④ 单条改动 ≤ 200 行，超出则拆下一轮。
- **产出**：`02-counterfactual/<条目>.md`。
- **边界**：审查期只允许为取证做最小改动，且**每条实验结束必须还原**；产品化改动不在本计划。
- **失败处理**：若「修复前」测不出失败 ⇒ 说明该条已修或原判断有误，按「已排除（带证据）」上账，不得强行造失败。

### T-10 门禁形式化审计（为什么欠账可以永远挂着）

- **目标**：找出「上限型 / 占比型」门禁——它们只防恶化，不防挂账，等于合法空过。
- **前置**：T-01。
- **输入**：`desktop/test/legacy-ledger.test.mjs`、`test/bridge-parity.test.mjs:107`、`test/ui-conventions.test.js:26`、`docs/harness-r7/legacy-ledger.json`。
- **必查项**：
  1. **死 bridge**：阈值「占比 ≤ 40%」，实测 53/246 = 21.5% ⇒ 19 个百分点余量，53 条可永久挂着。给「余量 = 阈值 − 实测」的算式。
  2. **裸 button**：`counts.rawButton <= 255`，实测 255 ⇒ 余量 0，一个都不清也通过。
  3. 同类扫描：全仓检索 `<=` / `>=` 与 BASELINE 常量，列出所有「以当前值为阈值」的门禁（这类门禁的语义是「不许变差」，不是「必须变好」）。
- **验收**：① 每条门禁给出「阈值 / 实测 / 余量 / 是 ratchet 还是 target」；② ratchet 清单完整（不得漏项：逐文件检索 BASELINE 常量）；③ 结论写清「这类门禁在什么条件下会真正生效」。
- **产出**：`05-closeout/门禁形式化清单.md`。
- **边界**：不改阈值（改阈值 = 消灭证据）。

### T-11 口径统一与收敛读数

- **目标**：把「同一个对象有两个数」全部登记并定口径，然后产出可现算的收敛指标。
- **前置**：T-02 ~ T-10。
- **输入**：本计划第 4 节的冲突登记表；`desktop/test/helpers/summary.mjs`。
- **步骤**：
  1. 逐条冲突项定口径（写「取哪个、为什么、另一个作废」）。
  2. 现算四个收敛指标：
     - 存量未闭环数 = 台账 `metrics.*.dead` 之和 + 本计划新上账且未闭环条数；
     - 假闸数 = W1 中「变异后仍绿」的门禁数；
     - 新代码首审缺陷率 = 本轮首次审查发现的 P0+P1 / 本轮涉及的新增代码行（`git diff --numstat` 累加）；
     - 同因复发次数 = 与第九轮 5 条 P1 同根因的条数。
  3. 每条指标给现算命令。
- **验收**：四个数字都有命令；换一台机器跑同一命令得同值；「通过」数必须扣除「跳过」（`通过 = 总计 − 失败 − 仅跳过`）。
- **产出**：`05-closeout/口径冲突登记.md`、`05-closeout/收敛读数.md`。
- **边界**：不得写死数字进报告正文而不给命令。
- **失败处理**：若某指标无法现算 ⇒ 标注「不可现算」并说明缺什么，不得估。

### T-12 干净检出复验

- **目标**：证明结论不依赖本机残留。
- **前置**：T-11。
- **步骤**：
  1. 所有实验改动已还原（`git status` 为空）。
  2. `git worktree` 新建于最终 SHA，跑完整套件。

## 4. 口径冲突登记（本计划发现的、必须在大规模取证前先定的）

| 对象 | 数 A | 数 B | 冲突性质 | 建议口径 |
|---|---|---|---|---|
| 数字员工目录规模 | 审计文档「66 个」 | 项目记忆与另一轮记录「51 条」 | 同一对象两个数，可能一方含模板/草稿 | **以目录实际条目现算为准**，并在报告里写「目录条目数」而非「员工数」 |
| 全量读数 | 10-24 审计「291 · 288 · 0 · 3」 | 今日记录「293 · 290 · 0 · 3 @ a20fe85」 | 检查项在增长，旧数过期 | 一律用 W0 基线现算值；引用旧数必须带 SHA |
| 「当前 HEAD」 | 审计文档 `38eebd6` | 实际 `08b874f` | 文档基线漂移 | 全文只写 SHA，不写「当前」 |
| 死 bridge | 台账「53 / 246 = 21.5%」；另一处提到「57 → 53」与「240 → 246」 | — | 分子分母同变，单看分子会误判「净减」 | 同时报分子、分母、比值三者 |
| 通过数口径 | 「通过 288」 | 「总计 291 − 失败 0 − 跳过 3 = 288」 | 表象一致，但有人会把「总计」当「通过」 | 一律写四元组（总/过/败/跳） |
