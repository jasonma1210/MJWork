## 二、逐项结果

### A-P0-6　`never` 档没有 L1 硬地板（已修）

**修复**：把 L1 判定提到 `never` 短路**之前**，并把两行合并成一条判据（净增 0 行）。
```js
const level = toolLevel(tool, args);
if (level === 'L1') return { need: true, level };
if (!level || approvalMode === 'never') return { need: false };
```

**行为验证**：
| 场景 | 修复前 | 修复后 |
|---|---|---|
| `never` + `rm -rf /` | 不询问 | **询问（L1）** |
| `never` + `write_file` | 不询问 | 不询问（保持） |
| `auto-safe` + `rm -rf /` | 询问 | 询问 |

**连带必须改的文案**：`approval.neverDesc` 原写「全部自动执行，不弹出任何确认」——行为变了文案不能继续撒谎。
> zh：文件写入与普通命令自动执行；危险命令（删除、强推、管道执行等）仍会询问
> en：File writes and normal commands run automatically; dangerous commands (deletes, force-push, piped execution) still ask

### A-P0-4　`apply_patch` 子进程缺 `error` 监听（已修）

**修复**：加 `child.on('error')` 转结构化失败 + `child.stdin.on('error')` 防 EPIPE；用 `settled` 收口（error / timeout / close 三条路径只认第一条）；`timer` **先声明**——`'error'` 事件与 `setTimeout` 赋值存在竞态，这是本项目记过的 TDZ 坑。

**连带发现并修掉的第二个缺陷**：patch 不可用时，上层会把错误改写为「补丁上下文与文件当前内容不一致，未做任何修改」，把排障方向从「装 patch」带偏成「改补丁」。已加前置判断直接透传真因。

**行为验证**：把 `PATH` 置空迫使 `spawn('patch')` ENOENT，返回 `{ ok:false, error:'patch 不可用（ENOENT）…' }`，**进程不崩**。

### A-P0-5　Windows 沙箱分支 Promise 悬挂（已修）

`windowsSandboxReady().then(async …)` 后补 `.catch`，三条异常路径（`ready()` reject / `applyWorkspaceAcl` 抛 / `execAsSandboxUser` 抛）不再让 `tool:shell` 永久挂起。异常时与既有分支同构 → 落命令守卫（仍过危险命令黑名单），不静默、不伪造成功。

> 不能行为断言的原因：该分支被 `process.platform === 'win32'` 门控，本机 darwin 无法进入。故退为结构性断言「`then(...)` 之后紧跟 `.catch`」。

### A-P0-1　熔断把前台一起挡死（已修）

**修复**：把 `isFg` 分支移出 `!breakerOpen` 判定，改为 `if (isFg) {…} else if (!breakerOpen) {…}`。

**行为验证**（实测，非推断）：
```
熔断阈值 5 次错误后触发
前台 fg: 拿到槽位 ✅
后台 bg: 被挡 ✅
```

### A-P0-7　`http_request` 的 DNS 层缺口（已修）

**修复**：新增 `assertResolvedPublic()`，复用 `ssrfGuard.guardedLookup`（语义=「全部解析结果都通过才放行」），在**每一跳** `fetch` 之前调用（含重定向后的新主机）。

**真实攻击路径验证**（不是构造用例，是真的 DNS 解析）：
```
toolHttpRequest({ url: 'http://127.0.0.1.nip.io:9/' })
→ { ok:false, error:'…127.0.0.1.nip.io 解析到 127.0.0.1（DNS 层拦截）' }
```
修复前它会通过字面量检查（`isPrivateHost('127.0.0.1.nip.io')` 为 false）然后 fetch 到内网。

**诚实标注残余风险**：`fetch`（undici）不支持 `lookup` 钩子，预检与实际连接之间理论上仍有权威应答轮换的窗口。这是纵深防御，不是绝对边界；彻底关闭需换成 `http.request` + `lookup` 钩子（webTools 已这样实现），列为后续重构项。

### A-P0-3　vm 沙箱可逃逸（**未彻底解决，已如实降级处理**）

这一项必须说透。

**实证**：
```js
vm.createContext({ Buffer, path })
Buffer.constructor.constructor('return process')()        → 'object'   // 拿到宿主 process
path.join.constructor.constructor('return process')()     → 'object'   // 同样能拿到
```

**这说明**：只要向 vm context 注入**任何**宿主函数/对象（`console.log`、`require` 白名单返回的 `path`/`util`/`crypto`），就存在 `fn.constructor.constructor` 通路。移除 `Buffer` 只是拿掉最廉价的那一条 —— **vm 不可能是安全边界**（Node 官方文档明确声明）。

**本次做的三件事（分层，不虚报）**：

1. **移除最便宜的逃逸面**：不再注入宿主 `Buffer` 与 `process.hrtime.bigint`（后者同样可 `hrtime.constructor.constructor`）。二进制需求走上下文原生的 `Uint8Array`。
2. **堵住「免审批执行」这条实际危害**：把逃逸原语纳入 `CODE_DANGER_PATTERNS`（`constructor.constructor` / `__proto__` / `.mainModule` / `globalThis.process`）。实测修复前 `isDangerousCode` 对两条真实 payload **都返回 false**，即会被当普通计算放行。
   验证：`sandbox_code_run` 基础 L2、命中逃逸原语升 **L1**；普通计算仍 L2（体验不变）。`code_exec` 同样受益。
3. **把「展示档」也改成同源**：审批卡摘要原硬编码 `level:'L2'`，命中 L1 时仍按普通色渲染 —— 用户看不到它其实是「恒确认的危险代码」。

**没做的（明确列为未解决）**：真正把子进程套进 OS 级沙箱（seatbelt/bwrap）。`utilityProcess.fork` 无直接挂钩，需改子进程启动方式，属架构级改动，不在批次 1 范围。**在它落地之前，「sandbox_code_run 是强沙盒」这句话在文档与 UI 上都不该被当成安全承诺** —— 它现在的定位是「防误用 + 抬高门槛」。

### A-P0-2　macOS 沙箱 fail-open（**部分误报，但仍修了真实缺口**）

审查报告说：「`checkCommandGuard` 仍认为有沙箱 ⇒ 跳过 30 条黑名单」。**核实结果：这条不成立。**

`tools/execFallback.js` 是 `checkCommandGuard` 的**唯一**调用点，它显式传了 `backendAvail = false`：
```js
const guard = sandbox.checkCommandGuard(policy, command, process.platform, false, false);
// 注释：已确认走到这里 = 本次没有 OS 级沙箱兜底，显式传 backendAvail=false，避免再走平台推断
```
这比报告建议的实现更严谨——不依赖平台推断，由调用方告知「本次无沙箱」。**黑名单实际是生效的。**

**但仍有一个真实缺口**，且在我当前环境里可复现：`defaultOsSandboxAvailable` 的 darwin 分支只看 `sandbox-exec` 二进制是否存在。而当 `seatbeltProbe` 已判定「不可用（嵌套沙箱）」时，两者结论打架 —— 一旦有人用默认参数调用，就会 fail-open。

**修复**：darwin 分支改为「有探测结果就以它为准，未探测才退回二进制推断」。
**本机实测**（本进程正跑在嵌套沙箱里）：
```
未探测 + execExists=true → 认为有沙箱
seatbeltUsable() → { ok:false, reason:'当前进程自身已处于 OS 沙箱内…' }
探测后 + execExists=true → blocked ✅（与 probe 同源）
```
