## 七、⚠ 唯一一处超出「仅前端」范围的改动

**`main/ipc/artifacts.js:51-63`（提交 `c6fc69c`，+11 −4）—— 需你追认，可否决。**

### 问题

原判据是「`projectId` 与 `threadId` 是不是都空」，但真正该判的是「传的是哪个」：

| 场景 | 修前 code | desk 显示 |
|---|---|---|
| 有会话、**未绑定项目**（最常见常态） | `NOT_FOUND` | 「找不到这条项目记录，**它可能已被移除**」——恐吓 |
| **根本没有会话** | `NO_PROJECT` | 「**这个会话**还没绑定项目空间」——虚指 |

最讽刺的证据在主进程自己手里：`NOT_FOUND` 分支的 error 字符串写的是「**该会话尚未绑定项目**」——文案承认是配置缺失，code 却声明数据不一致。而 desk 是第一个按 code 解释它的消费方，把一句本来准确的话转译成了恐吓。

### 修法

判据改为「传了 `projectId` 才可能是数据不一致；只传 `threadId` 就是未绑项目」。4 行，单文件，无新通道，无返回体结构变化。

### 为什么破例

1. 这是修 bug，不是改业务逻辑或实现思路
2. 不改没法救：desk 按 code 转译是对的，code 本身错了 ⇒ 两种文案必然有一个在撒谎
3. `ArtifactPanel.tsx:114-115` 只原样显示 `r.error`、不看 code ⇒ 消费方零改动
4. `bridge-parity` 自证：250 方法 / 197 引用 / 53 死桥，与改前完全一致

**如果你不接受这处改动，回退方式**：`git revert c6fc69c`，desk 会退回显示恐吓文案（其余功能不受影响）。
