## 0. 文档使用规则与结论摘要

### 0.1 四种陈述必须分开

本文使用以下标记，阅读与实施时不得混用：

| 标记 | 含义 |
|---|---|
| **【现状】** | 已由当前源码或既有测试证明存在的能力；只说明取证范围，不扩大结论 |
| **【目标】** | 已确定要做交互、数据或技术设计，但仍需实施与验收 |
| **【条件项】** | 依赖商业或外部决策，不进入默认本地版交付承诺 |
| **【实施前验证】** | 不是产品悬而未决，而是编码前必须核实的字段语义、环境能力或迁移条件 |

旧版报告中的“工作室没有一级入口”“助手没有数据源”“账本需要直接补成本/账单”“知识库弱可由关键词次数证明”等表述已过时或证据不足。本版以 2026-10-27 的重新取证为准。

### 0.2 已确定的产品决策

1. **Studio 是一级入口，目标是“空间 / 编制 / 看板 / 工件”四个 Tab。** 当前只完成空间与工件的部分装配，不能视为四 Tab 已完成。
2. **Assistant 路由 key 保持 `assistant`，可见名称统一为“助手”。** 默认页改为真实助手目录；保留发布任务与 AI 建团；AI 编制迁入 Studio。
3. **Ledger 是一级入口，但当前只做真实 Token 用量账本。** Desk 保留用量摘要和跳转，不再承担完整账本。没有价格、费率与金额数据，不展示成本、账单、发票或“¥”。
4. **知识库独立于记忆系统。** 记忆负责偏好与经验召回；知识库负责可导入、可授权、可检索、可删除、可引用的文档资产。
5. **真人协作采用无账号、无中心云的局域网主机模式。** 主机生成一次性邀请链接或邀请码，其他桌面端加入；Yjs 负责内容合并，主机权威命令负责成员、权限、审批和任务状态等不能靠 CRDT 自行决定的操作。
6. **AI 数字员工与真人成员是两套对象和权限体系。** AI 编制在 Studio；真人成员在“设置 → 团队”。邀请真人不会自动授予其管理 AI、使用工具或在主机执行任务的权限。
7. **生态中心不是助手目录。** 生态中心继续管理 MCP、技能与提示词包等扩展；助手目录消费真实数字员工目录，不复制插件市场概念。
8. **订阅、支付、价格与发票不进入当前本地版默认范围。** 未来若商业化，必须另行通过离线许可与商业规则评审，且不能因许可失效剥夺用户访问本地数据的权利。
9. **可观测性落在“设置 → 诊断与审计”，不新增一级导航。** 复用现有运行、审批、沙箱与审计事实，不另造一套运行状态。
10. **每个里程碑验收通过后再进入下一里程碑。** 不用静态演示、硬编码数据或仅有页面的空壳顶替真实能力。

### 0.3 核心问题不再是“有没有零件”，而是“能否形成可信闭环”

产品已经有 Agent、审批、沙箱、任务、数字员工、Token 流水、记忆和实验性协作零件。主要差距是：

- 用户能否从真实目录选助手，理解其能力与限制，再安全地派任务；
- 用户能否在同一项目上下文中管理空间、AI 编制、看板和工件；
- 用户能否核对每一次 Token 消耗，并以同一口径查看汇总和导出；
- 用户能否把业务文档变成可授权、可检索、可引用的本地知识资产；
- 小团队能否在没有账号和云服务的前提下，安全邀请、协作、离线和撤销；
- 所有页面能否一致处理加载、空、错误、权限、离线、迁移和无障碍状态。

## 1. 方法论：从能力盘点到可验收产品闭环

### 1.1 L0–L5 能力地图

| 层 | 产品问题 | 本文关注 |
|---|---|---|
| **L0 运行底座** | 敢不敢让它运行 | 审批、沙箱、审计、权限、诊断、数据安全 |
| **L1 单智能体循环** | 单个助手能否可靠工作 | 模型、工具、上下文、角色预设、知识注入、流式反馈 |
| **L2 多智能体编排** | 复杂任务能否拆解和协同 | 任务 DAG、调度、重试、AI 建团、运行状态 |
| **L3 人机协同** | 人能否理解、干预和接管 | 审批、接管、回放、协作冲突、可解释反馈 |
| **L4 组织与资产** | 能力能否沉淀和复用 | 助手、AI 编制、知识、项目、看板、工件、生态扩展 |
| **L5 经营与协作** | 用量能否核对，团队能否共同工作 | Token 账本、真人成员、局域网协作；订阅为条件项 |

L0–L5 用来避免只画页面、不检查底座；它不等于开发顺序。任何 L4/L5 页面若绕过 L0 权限与审计，仍判定为未完成。

### 1.2 每项能力必须回答的十个问题

所有需求按同一条链路展开，禁止停在“新增一个页面”：

**用户问题 → 当前证据 → 产品目标/非目标 → IA 入口 → 主任务流程 → 前端状态机 → 数据/IPC 契约 → 异常与权限 → 测试验收 → 指标与回滚。**

需求条目使用以下编号，便于从设计追踪到测试：

- `IA`：信息架构与跨页面逻辑；
- `AST`：助手目录与派单；
- `STU`：Studio；
- `LED`：Token 用量账本；
- `KB`：本地知识库；
- `COL`：局域网真人协作；
- `OBS`：诊断与审计；
- `SUB`：条件性商业许可；
- `NFR`：跨能力非功能要求。

### 1.3 优先级方法

采用“用户价值、闭环阻塞、数据真实性、依赖关系、安全风险”五项定性判断，不伪造 RICE 分数或用户规模。

| 优先级 | 含义 | 范围 |
|---|---|---|
| **P0** | 先统一主路径，避免后续能力继续挂错位置 | IA、Studio 目标四 Tab、助手目录与派单 |
| **P1** | 数据已经在本地或有明确本地实现路径，形成独立价值 | Token 用量账本、本地知识库 |
| **P2** | 小团队协作与条件性商业能力 | 局域网真人协作；订阅另受商业门禁约束 |
| **P3** | 在真实运行数据上提升诊断效率 | 统一诊断与审计视图 |
| **全程** | 每个里程碑都必须满足 | 安全、隐私、i18n、无障碍、性能、测试、迁移与回滚 |

优先级不是工作量估计，也不表示可以跳过依赖验证。

## 2. 产品定义、用户与任务

### 2.1 产品定位

MJ Nexus 是一个**本地优先、可监督、可沉淀资产的 Agent 桌面工作台**：个人可以从助手目录选择数字员工完成任务，在 Studio 管理项目与交付物，在账本核对 Token 使用；小团队可在同一局域网内共享指定空间并协作，而不必建立账号或把协作数据交给中心云。

“本地优先”不等于“所有处理永远不出本机”。对话、代码、文档和协作数据默认保存在本地或用户所在局域网；当用户配置的模型服务是远程服务时，发送给该服务的任务内容及获授权知识片段会离开本机，界面必须明确提示。

### 2.2 目标用户与 JTBD

| 用户 | 关键任务（JTBD） | 当前主要阻力 | 目标结果 |
|---|---|---|---|
| 独立创作者/自由开发者 | 想按专长选助手并快速派活 | 发布、编制与助手发现混在一起 | 从真实目录选择、预览限制、提交并追踪结果 |
| 一人工作室负责人 | 想围绕一个项目管理团队、任务和交付 | 空间、编制、看板、工件入口分散 | Studio 内保持同一项目上下文 |
| 成本敏感的重度用户 | 想知道 Token 花在哪个项目/任务 | 只有配额摘要，没有流水读取面 | 流水、汇总与 CSV 同口径可核对 |
| 有业务资料的用户 | 想让助手依据自己的资料工作 | 记忆不是文档库，缺授权与引用 | 本地导入、检索、显式注入与真实引用 |
| 小团队负责人 | 想拉同事协作但不想建账号/上云 | 实验性同步不等于成员产品 | 一次性邀请、角色、撤销、离线恢复 |
| 编辑者/查看者 | 想按权限参与，不破坏主机 | AI 权限与真人权限容易混淆 | 明确的 editor/viewer 边界与只读状态 |

### 2.3 核心用户闭环

1. **发现闭环**：打开助手 → 搜索/筛选 → 查看真实能力 → 检查运行条件 → 建立任务草稿。
2. **执行闭环**：选择项目 → 确认角色预设、工具和审批边界 → 提交 → 查看运行/审批 → 得到结果。
3. **资产闭环**：项目任务进入看板 → 结果成为工件 → 需要复用的资料进入知识库 → 后续任务显式引用。
4. **核对闭环**：Desk 看到摘要 → 进入账本 → 按项目/任务筛选 → 核对流水与汇总 → 导出 CSV。
5. **团队协作闭环**：主机开启共享 → 发出一次性邀请 → 成员加入并同步 → 按角色编辑/审批 → 离线恢复或撤销成员。

### 2.4 产品原则

- **真实优先**：没有数据就显示空态或缺失原因，不生成评分、价格、成本、引用或成功状态。
- **单一归属**：一个能力一个主入口；其他位置只做摘要或深链接。
- **项目上下文明确**：不能用路径字符串代替项目 ID，也不能把资产静默塞进隐藏的 `default`。
- **权限默认收敛**：默认不共享、不远程执行、不自动批准；高风险操作 fail-closed。
- **本地可退出**：邀请可撤销、知识可删除、导出可取消、功能可回滚，用户始终能读取自己的本地数据。
- **不重复造状态机**：页面编排状态必须映射到既有任务、审批和同步事实，不能另造互相矛盾的成功状态。

### 2.5 当前目标与非目标

**当前目标**

- 完整设计上述 IA、助手、Studio、Token 账本、知识库、LAN 协作与诊断能力；
- 让每个实施团队能从文档得到页面、状态、数据、权限和验收依据；
- 保留本地优先、无登录、无公有云、仅 zh-CN/en-US 的约束。

**当前非目标**

- 不做公有云协作、NAT 穿透、互联网中继、云备份或多主机集群；
- 不做真实支付、自动扣费、发票、税务或财务结算；
- 不将现有记忆直接改名为知识库；
- 不将插件市场复制成助手目录；
- 不让 CRDT 自动合并结果取代权限判定或审批决策；
- 不承诺移动端、浏览器公网版或任意规模团队；
- 不在本轮写生产代码或把目标设计标记成已上线。

- 不把当前 quota 窗口聚合复制成流水，也不以 Token 乘一个假设单价；
- 不把 memory 列表外包一层就称为知识库；
- 不把打开 Yjs HTTP 端口称为可邀请、可授权的多人协作；
- 不把邀请链接中的 `editor` 字样当作真实权限，所有权限由主机重新校验；
- 不做只有 UI 没有数据源、没有权限或没有验收的功能勾选。

### 4.2.1 资源作用域与 ID 契约

`workspaceId / projectId / spaceId` 不是同义词，首版基数固定如下，禁止由各页面自行猜测换算：

| 对象 | 定义与基数 | 授权规则 |
|---|---|---|
| `workspaceId` | 一份本地应用数据所在的逻辑工作区；一个工作区可有多个项目，不等于文件目录 | 本地 owner 可管理其中有权限的资产；LAN 访客没有整个 workspace 的默认访问权 |
| `projectId` | 任务、run、知识授权、工件和账目的 canonical 业务项目 ID | thread/task/run/artifact 必须能追溯到唯一项目；projectPath 仅是执行目录 |
| `spaceId` | LAN 共享边界；首版一个 space 只映射一个 project，一个项目最多有一个活动共享 space | 主进程维护 space↔project 映射；访客只能访问该 space 对应项目及显式共享资产 |
| `docId` | 协作文档 ID，必须带 space/类型/对象命名空间 | 不能用裸 docId 跨空间读取；主机逐消息校验映射 |
| 知识 source | 属于本地 workspace，通过 `knowledge_source_projects` 与项目多对多授权 | workspace 归属不意味着对所有 LAN 成员可见；共享仍按 space/project 判定 |

所有接口只接收其所需的 canonical ID，由主进程解析映射并鉴权；渲染进程不能同时提交互相矛盾的 spaceId/projectId 让后端任选其一。跨项目知识只在本地 owner 的“全部知识/未授权”视图管理，LAN 访客只能看到当前共享项目范围。

### 4.3 用单一页面状态替代布尔值叠加

【目标】路由状态至少包含：

| 字段 | 说明 |
|---|---|
| `page` | `new / desk / assistant / studio / scheduled / ledger / dashboard / thread` 中一个主页面 |
| `assistantTab` | 仅 Assistant 有效：`directory / publish / aiTeam` |
| `studioTab` | 仅 Studio 有效：`space / roster / board / artifacts` |
| `projectId` | 需要项目上下文时显式存在；不使用 projectPath 充当身份 |
| `threadId` | 仅对话/运行上下文使用 |
| `overlay` | `none / ecosystem / settings`，与主页面分开 |
| `overlayPayload` | 设置分区、生态详情等；不得保存邀请 secret |

实现可先用现有 React 状态和 `useReducer` 收敛，不要求为该设计引入新框架。迁移期可以保留 `showDesk/showStudio/...` 适配器，但适配器不是长期真源。

【迁移期兼容】若暂时保留 [navState.ts](file:///Users/jianma/Desktop/MJCode/desktop/renderer/src/lib/navState.ts#L64-L77) 的优先级函数，新状态顺序必须显式定义为：

`desk > studio > ledger > scheduled > assistant > ecosystem > dashboard/thread > new`

这只是防止旧调用方出现双高亮的过渡规则。目标实现通过单一 `page` 让非法组合不可表示。

### 4.4 导航、返回与草稿保护

- 点击一级入口只改变一个主页面；同一时刻最多一个一级导航高亮。
- 打开生态或设置保留底层页面；Esc/关闭后回到原页面和触发控件，焦点一并恢复。
- 返回操作先关闭覆盖层，再恢复同一页面的上一个安全状态；不能覆盖未保存草稿。
- Tab 切换只挂载活动视图，避免多列表同时请求；各 Tab 的滚动、筛选和草稿按 `projectId + tab` 保存在视图状态中。
- 页面切换不丢弃任务草稿；项目切换会改变可写范围，存在脏草稿时先询问“保留草稿并停留 / 丢弃并切换”，不能静默带往另一个项目。
- 重新启动只恢复安全路由和筛选；不自动打开含敏感内容的邀请确认框，不自动重放提交、审批或导出。
- 所有深链都要做资源存在性和权限校验；资源不存在时显示可返回的空态，而非跳到无关项目。

### 4.5 跨页面统一异步模型

每个远程/IPC 资源至少有 `idle / loading / ready / empty / refreshing / error / forbidden / offline` 的展示语义：

- 首次加载显示骨架或明确进度；后台刷新保留旧数据并标出“正在更新”，不能闪空。
- 空态区分“没有数据”“筛选无结果”“没有权限”“索引未就绪”“主机离线”。
- 每次请求携带递增 requestId 或取消句柄；旧响应不得覆盖新筛选、新项目或新页面。
- 错误提供可理解的 i18n 文案和可行操作：重试、修改筛选、检查配置、重新连接；不只发一个短暂 toast。
- 提交类操作进入 submitting 后禁止重复点击，以业务 ID/幂等键防重；超时不能自行把失败改成成功。
- 权限错误不通过“隐藏按钮”单独处理；主进程仍必须重新校验。

## 5. Assistant：真实助手目录与派单闭环

### 5.1 产品目标与边界

【目标】用户进入 Assistant 后先看到真实数字员工目录，可以理解“它能做什么、需要什么配置、当前能否运行”，再把所选角色带入现有任务主链路。

本期不做助手评分、付费市场、云端发布、用户评论或虚构“最常用”。51 个数字员工是当前数据快照，不在 UI 固化为固定数字。

### 5.2 页面结构与前端逻辑

**目录默认页**

1. 顶部：页面标题、搜索框、可用状态筛选；有真实标签时才显示标签筛选。
2. 列表：名称、角色定位、真实描述、能力/标签、运行状态；无数据字段就省略，不补写营销信息。
3. 详情：角色说明、真实工具/技能/模型要求、审批与沙箱摘要、runtime 状态、主要操作“使用该助手”。
4. 派单抽屉或页面：项目、任务目标、所选助手、将应用的角色预设、知识范围（KB 里程碑后）、审批提示、提交按钮。
5. 发布任务与 AI 建团继续作为独立 Tab；AI 建团结果进入 Studio 编制，而不是创建另一套助手目录。

目录只有约 51 项时可优先使用主进程一次性目录结果 + 前端搜索/筛选，不为简单搜索新增无必要服务。runtime 按选中项或可见项查询并缓存，避免每次打开页面进行无界 N+1 请求。

### 5.3 主任务流程

```text
加载目录
→ 搜索/筛选（可选）
→ 查看详情
→ 查询 runtime 与依赖
→ 点击“使用该助手”
→ 选择项目并编辑任务草稿
→ 预览实际 rolePreset 将改变的 prompt/tools/approval/sandbox/skills/model，并固定 presetVersion/policyHash
→ 用户显式提交该版本
→ 主进程比对版本后，复用现有 agent:run + rolePreset 主链路；版本变化则拒绝并要求重新预览
→ 跳转对话/运行视图
→ 后续审批、结果与工件仍走现有 canonical 状态
```

“启用助手”和“提交任务”是两个明确动作时，界面要分别反馈；若合并为一个按钮，也必须在确认摘要中说明将发生的配置变更。卡片单击、搜索或查看详情绝不能触发执行。

### 5.4 状态机与异常

| 对象 | 状态 | 前端行为 |
|---|---|---|
| 目录 | loading / ready / empty / error | error 可重试；empty 显示真实目录为空及生态/配置出口，不放假数据 |
| 搜索 | 有结果 / 无结果 | 无结果保留原目录并给“清除筛选”，与目录为空区分 |
| runtime | unknown / checking / ready / needs-setup / unavailable | needs-setup 跳具体设置；unavailable 禁用提交并说明原因 |
| 草稿 | pristine / dirty / invalid / ready | 离开保留；缺项目或目标时行内提示 |
| 提交 | idle / validating / applying-preset / submitting / handed-off / failed | handed-off 后以既有 run 状态为准；failed 保留草稿并允许安全重试 |

如果角色预设要求扩大工具、网络、文件写入或模型权限，必须重新进入现有审批逻辑；不能因为是“官方助手”而静默提权。远程模型会收到的内容需在提交前可见。

### 5.5 数据与接口复用

| 契约 | 使用方式 | 约束 |
|---|---|---|
| `ecosystem:employee-catalog`（现有） | 目录真源 | 返回结构先做 schema 校验；缺少可选字段时 UI 省略 |
| `ecosystem:employee-runtime`（现有） | 运行条件与状态 | 不根据目录描述猜 ready；错误状态可重试 |
| `agent:run` + `rolePreset`（现有，目标扩展版本参数） | 提交到真实执行链 | 请求携带已预览的 presetVersion/policyHash；主进程重新读取并比对后再应用，不一致返回 `PRESET_CHANGED`；渲染进程不能直接覆盖安全策略 |
| `rolePresetApply.js`（现有） | 统一角色预设应用 | 不在 Assistant 内另写一套 prompt/tool 注入逻辑；目标需让预览与执行消费同一版本化预设快照 |
| employee runtime chain test（现有） | 回归基础 | 新 UI 需补目录→草稿→提交端到端测试，而非只测纯函数 |

【实施前验证】确认目录 ID、rolePreset ID 与 runtime ID 的稳定映射；确认“启用/recruit”对本地配置的写副作用；若字段映射不稳定，先修数据契约，不在卡片层硬编码名称匹配。

### 5.6 AST 验收

- 首次打开 Assistant 默认是目录，目录条数与真实数据源一致；无伪造评分/价格。
- 搜索、组合筛选、清空筛选、目录为空、检索无结果、加载失败都有独立状态。
- 缺少模型/工具/技能时不能显示“可运行”；修复配置后状态可刷新。
- 使用某助手提交后，实际 run 可追溯到该 rolePreset，安全策略没有被渲染层绕过。
- 双击/重试不会重复创建任务；失败后草稿仍在；预览后预设或安全策略发生变化时返回 `PRESET_CHANGED`，不得按未确认的新版本执行。
- 编制不再出现在 Assistant；旧链接只到 Studio roster。
- zh-CN/en-US、全键盘操作和读屏均能完成选助手到提交的主流程。

## 7. Ledger：真实 Token 用量账本

### 7.1 产品定义与命名

一级导航可显示“账本”，页面标题必须为“Token 用量账本”或同等明确文案。它回答：**什么时候，哪个项目/任务/运行/来源，记录了多少 Token。**

当前不回答“花了多少钱”。没有模型价格、输入/输出分价、币种、税费和折扣数据，因此禁止出现成本、账单、应收、发票、¥、$ 或估算金额。未来即使获得价格，也需要单独的数据来源、时间有效性和舍入规则评审。

### 7.2 页面结构

1. **上下文条**：项目筛选、时间范围（今天/近 7 天/自定义）、其他可用维度筛选、刷新、导出。
2. **摘要区**：筛选范围内记录数与 Token 总量；明确时区、数据更新时间与“本地真实流水”来源。
3. **趋势与分布**：按日趋势，按项目/来源等真实字段分布；无数据时显示空图，不生成示例折线。
4. **明细表**：时间、项目、任务、运行、来源、member 原始语义标签、Token；点击 task/run 进入对应详情。
5. **导出**：导出当前筛选的原始流水，显示范围与行数；可取消，完成后给本地文件路径。
6. **Desk UsageCard**：继续显示窗口配额摘要，提供“查看用量账本”；不要把窗口摘要与自定义流水汇总混为同一数字。

助手、模型、输入/输出 Token 维度只有在映射或字段真实存在后才能开放。`member_id` 在语义核实前显示为通用成员标识或不作为筛选项，不能直接改称“真人成员”或“助手”。

### 7.3 查询一致性与数据契约

【目标】新增接口是设计契约，名称可随工程规范调整，语义不能省略。

| 目标通道 | 请求 | 响应/副作用 |
|---|---|---|
| `ledger:query` | 首页传标准化 filters、sort、limit、summaryDimensions；后续页传含 filtersHash/asOf/末位键的不透明 cursor | 同一 SQLite 读快照中的 items、summary、nextCursor、normalizedFilters、asOf、fieldAvailability；所有后续页沿用首页 asOf |
| `ledger:export` | 同一 normalizedFilters + asOf、用户选择的目标路径 | 后台流式 CSV；返回 exportId、进度、完成/取消/失败状态 |
| `ledger:capabilities` | 无 | 可用筛选维度、最大 page size、导出能力、字段语义版本 |

通用约束：

- filters 至少支持时间闭开区间 `[from,to)`、projectId、taskId、runId、source；其他维度由 capabilities 决定是否显示。
- UI 用本地时区选择/展示，IPC 使用带时区的 UTC ISO 时间；实现前确认现有 created_at 的单位与历史值。
- 默认按 `(created_at, id)` 倒序做 keyset 分页。若现有表没有稳定唯一且单调递增的 consumption id，先迁移补齐；不得只用相同时间戳分页。
- `asOf` 明确定义为**单调 consumption id 高水位**，不是 created_at 时间上限。原始列表和汇总共用同一个规范化查询构造器及读事务；首页返回的 asOf 被固化进不透明 cursor，后续所有页必须同时满足 cursor 的 filtersHash 和 `id <= asOf`，不能用同 asOf 偷换筛选。导出沿用同一过滤器和 asOf，因此查询后新增的流水即使补写了较早 created_at，也不会混入后续页或该次导出；只有用户显式刷新才获取新高水位。
- 所有 SQL 参数化；排序字段、维度、来源枚举使用白名单，不拼接渲染进程传入的 SQL。
- 账本只读、流水 append-only；本里程碑不提供编辑/删除。未来纠错使用带原因和关联 ID 的调整记录，不改历史事实。
- 渲染进程不直接打开数据库，不接受任意文件路径；导出路径来自系统保存对话框。

### 7.4 CSV 口径与安全

- UTF-8、RFC 4180 转义；列名使用稳定英文 snake_case，UI 提供中英文字段说明。
- 原始流水和汇总不能混在同一个“总计行”里破坏后续机器处理；本期 CSV 只导出流水。
- 导出包含当前筛选的所有行，而非当前页；分批读取、可取消、目标文件写入失败要保留明确错误。
- 对以 `=、+、-、@` 等开头的文本单元格做电子表格公式注入防护；数字 Token 保持数值。
- 文件名不包含密钥、完整本地路径或任务正文；导出行为写本地审计，不记录敏感内容。

### 7.5 状态与异常

| 场景 | 目标表现 |
|---|---|
| 无流水 | 显示“尚无 Token 使用记录”，汇总为 0，不显示示例数据 |
| 筛选无结果 | 保留筛选条件和全局数据存在的事实，给清除筛选 |
| 历史字段缺失 | 对应单元格显示“未记录”，维度不出现在图表中 |
| 查询失败/数据库忙碌 | 保留旧数据并标过期，可重试；不能把失败当 0 |
| 新记录到达 | 提示有更新；刷新后重置 cursor，防止分页重复/遗漏 |
| 导出中导航离开 | 导出在主进程继续，重新进入 Ledger 可查看状态；应用退出时按规则取消并清理临时文件 |
| 无权限（M4 的 LAN 场景） | 仅主机 owner 查看完整账本，访客不能通过构造 IPC/WS 绕过；M2 只验本机权限 |

### 7.6 实施前验证与 LED 验收

【实施前验证】

- 核对 `quota_consumptions` 完整表结构、唯一键、created_at 单位、tokens 口径、source 枚举、member_id 真实含义；
- 核对一次 Agent round 可能写几条记录，避免把“记录数”表述成“任务数”；
- 核对历史数据迁移与 quota snapshot 的窗口边界，不强制两个不同口径的数值相等；
- 明确 run/task/project 的关联表与删除后的历史展示策略。

【验收】

- 写入一组已知测试流水后，明细合计、各维度汇总、趋势与 CSV 在同过滤器/asOf 下完全一致；
- 跨日、夏令时时区、相同时间戳、大结果集分页没有重复或遗漏；
- 任意筛选无数据时不出现假图表，查询失败不被显示为 0；
- 没有金额或推测成本；没有真实字段的维度不出现；
- CSV 覆盖全部筛选结果、可取消、能抵抗公式注入；
- M2 验证 append-only、参数化查询、本机权限与审计；M4 再以 LAN owner/editor/viewer 验证完整账本仅 owner 可用，且导出不能被访客构造请求绕过。
- 首页查询后新增一条补写历史 created_at 的流水，其更大 consumption id 不得进入旧 asOf 的后续分页、汇总或 CSV；显式刷新后才进入新快照。

## 8. 本地知识库：文档资产、检索与可信注入

### 8.1 为什么不能复用 Memory

| 维度 | Memory | Knowledge Base |
|---|---|---|
| 目的 | 偏好、经验、上下文召回 | 用户显式管理的文档事实与业务资料 |
| 生命周期 | 可衰减、去重、受容量策略影响 | 明确导入、版本、授权、更新、删除 |
| 检索 | 为提示词自动评分和召回 | 可搜索、可预览、可筛选、可追溯 chunk |
| 权限 | 服务个人上下文 | 以项目授权，LAN 下还要按共享范围与真人角色校验 |
| 引用 | 不保证稳定文档定位 | 有 source/chunk/可用定位信息，无定位则不伪造 |

两者未来可以协同，但不能共用名称来掩盖生命周期和权限差异。

### 8.2 范围与信息架构

【目标】知识库是本地工作区级文档资产，通过显式授权供一个或多个项目使用。主管理入口在 Studio → Space → 知识库；本地 owner 可切换“当前项目 / 全部本地知识 / 未关联项目”视图，后者用于管理已导入但尚未授权给任何项目的文档。LAN 访客没有 workspace 全量视图，只能看到当前共享项目获授权的内容。任务侧只提供“选择知识范围、预览将注入内容、查看引用”。

首里程碑支持文本类文档与可解析的 PDF/DOCX，具体格式以主进程 capabilities 返回为准。M3 只交付本机文件导入与读取；M4 若允许访客上传/下载，必须同时交付第 9.6.1 节的鉴权二进制传输，不能用 Yjs 文本同步冒充文件传输。加密、损坏、扫描无文本或解析为空的文件进入明确失败/部分成功状态，不能假装已索引。整库自动同步、网页爬虫、云网盘和云端向量服务不属于首里程碑。

### 8.3 数据模型（目标）

| 表/对象 | 关键字段 | 作用 |
|---|---|---|
| `knowledge_sources` | id、workspaceId、title、originalName、contentHash、currentSourceVersion、mimeType、parserVersion、status、errorCode、size、createdAt、updatedAt | 一份文档的身份、当前版本、解析版本与生命周期 |
| `knowledge_chunks` | id、sourceId、sourceVersion、ordinal、text、tokenCount、locatorJson、contentHash | 稳定分块与真实引用；页码只有解析器提供时才保存 |
| `knowledge_source_projects` | sourceId、projectId、authorizedBy、createdAt | 项目级显式授权；授权不等于复制文档 |
| FTS 索引 | chunkId、规范化检索文本、schemaVersion | BM25/FTS 查询；可从 sources/chunks 重建 |
| 导入任务 | importId、sourceId、阶段、进度、errorCode、retryable | 前端进度、取消和失败重试 |

项目安全元数据维护单调递增的 `projectAuthzRevision`，每次知识授权/撤权/项目共享范围变化都在同一事务中递增；每个 actor 另有 `actorAuthzEpoch`，角色、成员状态或凭据批次变化时递增。撤权后再授权、降级后再恢复也会产生新版本，旧 contextPlan 不得因最终状态看似相同而复活。

相同 contentHash 可以复用物理内容，但项目授权必须独立；不能因为另一个项目已导入相同文件就自动授权。文档更新先构建新版本，新版本 ready 后原子替换当前版本；失败时继续保留旧的可用版本。

### 8.4 导入、更新与删除流程

```text
系统文件对话框选择文件
→ 主进程校验大小/类型/路径并计算 hash
→ 复制到应用管理的本地存储
→ queued → parsing → chunking → indexing → ready
→ 用户选择项目授权
→ 可搜索、可在任务中选择
```

- 多文件导入逐项显示状态，一个失败不吞掉其他成功项；失败项可按原因重试。
- 解析与索引在主进程/工作线程后台执行，UI 可取消；取消后清理未提交的临时资产。
- 删除需说明会移除索引、chunks 和授权；用户原始文件不被删除，除非未来另有明确选项。
- 已有运行记录若为审计保存了引用摘要，删除文档不能暗中改写历史；UI 要说明这些副本，并提供单独清理运行历史的入口。
- SQLite WAL、备份或导出可能仍含已删除内容，不承诺物理安全擦除；高敏场景需额外数据销毁策略。

### 8.5 中文/英文检索技术门槛

【实施前验证】先验证当前 better-sqlite3/SQLite 构建是否启用 FTS5，以及中文召回效果，再进入完整 UI 实施。

目标检索采用：

- 英文按词元、大小写与基础规范化处理；
- 中文采用经过测试的 bigram 或等效分词方案，不能假设 `unicode61` 能正确按中文词搜索；
- FTS/BM25 只做词法相关性排序，分数不能显示成“可信度百分比”；
- 查询转义、参数化并限制长度；结果摘要转义后高亮，禁止文档 HTML 注入；
- 无命中返回真实空态，不生成“相关答案”；索引不可用返回 `INDEX_UNAVAILABLE`，不能静默换成低质量全表扫描。

向量/嵌入检索不是首里程碑必需项。未来加入时必须另评本地模型、远程传输、索引版本和删除语义。

### 8.6 任务注入与引用

1. 用户在任务草稿中显式选择已授权 sources，或使用项目明确配置的默认知识范围。
2. 主进程根据任务内容检索，返回**检索候选** chunks；用户可移除不想发送的片段。候选只表示搜索命中，不能称为答案引用。
3. 用户确认预览后，主进程生成不可变 `contextPlan`：包含 planId/planHash、projectId、actorId、projectAuthzRevision、actorAuthzEpoch、精确的 currentSourceVersion、chunkId、chunkHash、排序、排除项与最终上下文预算。Renderer 可持有 ID 和预览，不能替换其中的文本。
4. `agent:run` 提交 contextPlanId/planHash，而不是仅提交范围后重新检索。主进程在**创建 run 的同一事务**中检查 actor 仍有效、projectAuthzRevision/actorAuthzEpoch 与所有 sourceVersion/hash 均未变化，读取 plan 固定 chunks 并写入该 run 的注入快照；随后执行只读此快照。任一不匹配返回 `CONTEXT_PLAN_STALE` 或 `FORBIDDEN`，保留草稿并要求重新预览，校验与快照之间没有撤权竞态。这样用户删除的片段不会因二次检索重新出现，撤权后再授权也不能复活旧 plan。
5. 注入采用统一上下文预算，保留 sourceId/chunkId/locator；预算不足时必须在预览中明确截断，不能声称已参考整份文档。
6. 文档内容一律标记为**不可信参考数据**。其中的“忽略规则、执行命令、泄露密钥”等文本不能改变系统指令、审批或工具权限。
7. UI 分开记录“检索候选、实际注入、输出引用”：输出引用只能是模型答案对实际注入 chunk 的可映射引用，并明确“引用不代表内容真实”；没有定位信息就显示文档与 chunk，不编造页码。未注入的搜索候选不得显示成答案依据。
8. 使用远程模型时，提交前提示将发送的文档片段；未授权知识不得因自动召回被带出项目。

### 8.7 目标 IPC 与权限

| 目标通道 | 职责 | 关键约束 |
|---|---|---|
| `knowledge:import` | 从系统对话框导入，返回 importId | 主进程校验路径、类型、hash；不可传任意目录批量读取 |
| `knowledge:list` | 按 `workspace / project / unassigned` 作用域与状态分页列出 sources | 本地 owner 可查 workspace/unassigned；LAN 访客只能查当前共享 project；actor 由主进程确定 |
| `knowledge:search` | 查询授权范围内 chunks | 返回真实 source/chunk/locator/snippet；无命中为空 |
| `knowledge:authorize` | 添加/移除项目授权 | 本地 owner 或主机授权角色；写审计 |
| `knowledge:delete` | 删除 source 及索引/授权 | 幂等；说明历史副本；不能删原始文件 |
| `knowledge:preview-context` | 检索候选并在用户确认后生成不可变 contextPlan | 固定 projectAuthzRevision、actorAuthzEpoch、sourceVersion/chunkId/hash、排除项与预算 |
| `agent:run` 扩展 | 提交 contextPlanId/planHash | 在创建 run 的同一事务重验授权/版本并写注入快照；不二次检索、不接收渲染层伪造文本；过期返回 `CONTEXT_PLAN_STALE` |

M4 的 LAN 默认只共享明确标记为共享的项目知识。viewer 可检索/阅读共享内容；editor 可在第 9.6.1 节资产传输落地后导入和提交草稿；删除与授权变更仅 owner。完整账本权限不因知识共享而开放。

### 8.8 KB 验收

- 中文、英文、混合语言、特殊字符、长文档均有检索测试；中文不是只能整串 LIKE 命中。
- 加密/损坏/空解析/超限/重复文件、取消、重试、索引失败和版本更新都有可见状态。
- M3 验证项目 A 的文档不能被本机项目 B 的任务通过猜测 ID 检索；撤权后新任务立即不可注入。M4 再以 LAN 访客重跑同一越权用例。
- 无命中时不生成引用；检索候选、实际注入和输出引用分别可见，引用可回到真实 source/chunk，页码不虚构。
- contextPlan 外被删除的片段不会在执行时复活；文档版本、授权或内容变化会使计划失效并要求重新预览；撤权后再授权、角色降级后恢复也会使旧 plan 失效，创建 run 与固定注入快照之间无授权竞态。
- 恶意文档文本不能改变审批、工具、沙箱或系统指令。
- 删除后搜索与授权消失，原始文件不受影响；历史引用副本的边界在 UI 可见。
- 索引和搜索不阻塞渲染进程，性能预算见第 14 章。

## 9. 无账号局域网邀请与多人协作

### 9.1 已选方案与适用边界

【目标】一台桌面端作为主机，其他桌面端通过同一局域网加入被共享的空间。无账号、无密码体系、无中心云；成员以主机签发的可撤销设备凭据识别。

适用：2–8 人、互信的小型团队、同一 LAN。  
不适用：跨公网、NAT 穿透、主机长期离线仍写入、多主机故障转移、匿名公开协作。

主机离线时，所有客户端显示同步暂停：可读取已缓存的共享内容；editor 的普通内容编辑可离线排队，viewer 始终只读；审批、邀请、角色变更、撤销和执行等权威命令不自动离线重放。离线更新必须保留 actor/device/origin 来源信息；重连后先按**当前角色**重新授权本人队列，降级为 viewer、撤销或空间共享关闭后不得把原 editor 队列自动写入，只能保留本地副本供导出或人工处理。

### 9.2 混合权威架构

| 内容/操作 | 同步或决策方式 | 原因 |
|---|---|---|
| 协作文本、普通草稿、卡片描述 | **可写内容文档**中的 Yjs CRDT 合并，更新带 actor/device/origin | 多人编辑可收敛，离线内容可按当前权限重新校验 |
| 看板位置/状态、任务指派 | 带版本的主机命令；结果写入独立的**主机权威投影**，客户端只有只读同步通道 | 要维护任务状态机和业务不变量，客户端直接伪造 Yjs 更新不能改变权威事实 |
| 邀请、角色、撤销、项目共享范围 | 主机权威命令；成员表不开放 CRDT 写路径 | 权限不能由并发 CRDT 合并决定 |
| 审批、工具执行、远程运行 | 主机权威命令 + 现有审批/沙箱 | 高风险操作必须 fail-closed |
| 在线状态/光标 | 临时 presence，不落审计 | presence 不是事实日志 |
| 审计与命令回执 | 主机 append-only 记录 | 可追溯、可去重、可检查 |

可写内容文档与权威投影必须使用不同 docId/通道和写权限。访客即使在本地篡改权威投影或向内容通道提交同名字段，主机也只把权威命令结果写入权威存储，并在下次同步覆盖客户端视图；“客户端画面被改”不等于“主机事实已改”。

现有 Yjs/collab 是可复用底座，但实施前必须审查 `/collab/docs/:docId/sync` 的 authMiddleware 是否真正覆盖 HTTP 与 WebSocket 升级、文档级授权、消息大小和连接生命周期。未通过审查前继续保持 collab 默认关闭。

### 9.3 邀请与加入流程

**主机侧**

1. owner 在 Settings → 团队选择要共享的空间，启动 LAN 共享；默认绑定 LAN，不绑定公网地址。
2. 系统生成短期、一次性邀请。默认建议 15 分钟有效，可在创建前调整短时限；界面显示过期时间。
3. 完整邀请链接包含：协议/schema 版本、spaceId、inviteId、一次性 secret、hostId、主机地址/端口、证书指纹、过期时间、拟授予角色。拟授予角色首版只能是 editor 或 viewer，owner 不通过邀请产生。
4. 主机只保存 invite token 的加密哈希和必要元数据；完整链接/邀请码只在创建时展示，不出现在日志、埋点或崩溃报告。短邀请码本身不包含全部连接信息，必须同时由用户输入主机地址/端口并核对证书指纹，或通过经过同等指纹校验的 LAN 发现流程补全；不能只凭短码宣称可加入。

**访客侧**

```text
粘贴链接/邀请码
→ 校验格式、版本、过期时间
→ 连接候选主机并校验 WSS 证书指纹
→ 预览空间名称、主机身份和申请角色
→ 用户确认
→ 主机原子校验“未使用 + 未过期 + 未撤销 + 空间仍共享”
→ 一次性 invite 被消费
→ 换发独立 memberId/deviceId/credential
→ credential 存入本机 safeStore，主机只存哈希
→ 初始同步 → online
```

邀请预览不能消费邀请；兑换必须原子，两个客户端同时使用同一邀请最多一个成功。邀请 secret 不等于长期成员凭据，撤销邀请不应撤销已加入的其他成员。

证书指纹不匹配、版本不兼容、地址不可达、邀请过期/已用/撤销分别给出错误；不得提供“忽略证书继续”的按钮。客户端持久化 hostId 与证书 pin。主机 IP 变化后，已加入成员可手工更新地址并用原 pin + 已有凭据重连，而不是反复创建新身份；若证书轮换导致 pin 改变，必须由 owner 通过带外可信渠道提供并人工核对新指纹，不能由网络响应静默替换。

### 9.4 成员、角色与权限矩阵

| 能力 | owner | editor | viewer |
|---|---|---|---|
| 查看共享空间/看板/工件/共享知识 | 是 | 是 | 是 |
| 编辑协作文本、卡片描述、任务草稿 | 是 | 是 | 否 |
| 修改看板状态/指派 | 是 | 是，受任务规则约束 | 否 |
| 导入共享知识 | 是 | 是 | 否 |
| 删除知识、改变项目授权 | 是 | 否 | 否 |
| 管理 AI 编制、模型、工具与安全策略 | 是 | 否 | 否 |
| 邀请、改角色、撤销成员 | 是 | 否 | 否 |
| 审批危险操作 | 是，在主机上 | 否 | 否 |
| 在主机发起 Agent 执行 | 是 | 默认否；需独立开启远程执行并仍受审批 | 否 |
| 查看完整 Token 账本/导出审计 | 是 | 否 | 否 |

- 首版每个空间一个 owner，且 owner 只在主机本机操作；邀请不能创建第二个 owner。owner 的审批竞态测试针对同一主机的两个窗口或重复命令，不虚构“多个 owner 客户端”。所有权转移、owner 多设备与主机永久丢失恢复另行设计。
- 首版一个访客 member 对应一个活动 device；一次性邀请原子兑换这一对 memberId/deviceId/credential。更换设备需撤销旧设备后重新邀请，不允许多个设备共享同一凭据。owner 不支持通过普通“改角色”被降级或撤销。
- editor/viewer 显示名不充当身份；内部 memberId/deviceId 唯一。显示名可重复，审计记录不可混淆。
- 成员可主动离开；owner 可撤销设备/成员。撤销后主机断开现有连接并拒绝新同步，已缓存到对方设备的数据无法保证远程擦除，UI 必须诚实说明。
- 邀请不授予整个主机或其他项目访问权；每个同步消息都以连接对应的真实成员和空间重新鉴权。

### 9.5 权威命令、幂等与冲突

每条权威命令至少带 `commandId、spaceId、actorId、deviceId、clientSeq、schemaVersion、baseVersion、payload、payloadHash`。actorId 还必须与连接凭据匹配，不能由 payload 自称；回执绑定 commandId + actorId + spaceId + payloadHash。

主机处理顺序：

1. 校验连接身份、活动成员、空间可见性、命令基本形态和 schema；撤销成员不能借“查回执”继续访问；
2. **先查持久化命令回执**：同 actor/space 下 commandId 与 payloadHash 相同的重试直接返回原回执，不再因 baseVersion 已过时而误报冲突；同 commandId 但 payloadHash 不同则返回 `COMMAND_REUSE` 并拒绝；
3. 对新命令校验当前角色、资源 baseVersion 与业务状态；
4. 在同一本地事务中写业务事实、命令回执和审计，保证崩溃恢复后仍可去重；
5. 广播权威版本及同步游标。

并发审批同一个请求时，第一条合法决策成功，后续新命令收到 `CONFLICT` 并刷新，同一命令重试则收到原回执；不能出现两个窗口都显示“自己批准成功”。离线排队的普通 CRDT 内容只有在当前角色仍允许时才可合并，离线权威命令只保存为草稿，重连后让用户确认再提交，尤其是审批、执行和删除。

### 9.6 同步状态机与前端反馈

| 对象 | 状态 | 必须表现 |
|---|---|---|
| 主机共享 | stopped / starting / listening / degraded / error | 绑定地址、空间、证书指纹、在线成员；启动失败不显示已共享 |
| 邀请 | active / redeemed / expired / revoked / exhausted | 列表不显示 secret；可撤销 active；状态来自主机 |
| 成员 | active / revoked / left / offline | offline 是 presence，不等于 revoked；权限展示以 active 为准 |
| 客户端同步 | disconnected / connecting / validating / syncing / online / offline-cache / incompatible / forbidden | 显示最后同步时间、缓存/排队数量、重试与退出共享 |
| 命令 | draft / pending / accepted / rejected / conflict / unknown | unknown 时先查询回执，不能盲目重放 |

网络重试采用有上限的退避与抖动；页面不能永久 spinner。断线后保留缓存并醒目标注“可能不是最新”。队列损坏、schema 不兼容或权限变化时停止自动同步并保留用户数据导出路径。

### 9.6.1 二进制资产传输与缓存

Yjs 只同步元数据和协作内容，不承载知识原文件、工件二进制或大型附件。M4 必须补经同一成员凭据鉴权的主机 HTTPS 分块传输：

- 上传由访客主进程读取用户通过系统对话框选择的文件，以 assetId、spaceId、分块序号、offset、SHA-256、大小和 MIME 元数据发起；主机逐块校验空间、当前角色、配额和长度，写入临时区。
- 完成时校验整文件 hash，再以事务把资产与项目/知识 source 绑定；hash 不符、取消或权限变化时清理临时块。断点续传只允许同一 actor/device/assetId，不能接管他人上传。
- 下载按 assetId 重新鉴权，支持 Range/分块、取消和 hash 校验；访客只能用系统保存对话框选择目标位置，不能指定主机路径或遍历主机文件。
- 共享知识/工件的权威存储在主机，访客缓存有 spaceId/assetId/hash 命名空间、容量上限和清理规则；撤销后不能继续从主机下载，已有本地缓存仍遵守“无法保证远程擦除”的诚实边界。
- 大文件不一次性读入 Renderer 或塞进单条 IPC/Yjs 消息；上传、下载、索引分别展示进度和失败原因。editor 的“导入知识”只有在这套传输完成后才可对 LAN 开放。

### 9.7 传输、存储与隐私

- 同步仅 WSS、资产传输仅 HTTPS；两者使用同一 hostId/证书 pin 体系，自签证书通过邀请或带外核验的指纹固定，凭据和 secret 不明文落盘。
- safeStore 不可用时阻止加入或明确进入不支持状态，不能降级为明文存储。
- 限制消息大小、频率、连接数和同步文档范围，避免局域网内拒绝服务；所有输入做 schema 校验。
- 协作不经过中心云，但远程模型仍可能收到共享任务/知识内容，按原模型隐私提示处理。
- 审计记录成员、角色、邀请、撤销和权威命令元数据；不记录 invite secret、credential、API key 或完整敏感正文。
- 本地备份由用户显式执行；不承诺云备份、跨网络访问或主机磁盘损坏后的自动恢复。

### 9.8 目标控制接口与现有模块关系

| 目标通道 | 职责 |
|---|---|
| `team:host:start/status/stop` | 管理指定空间的 LAN 服务，不暴露任意 HTTP 路由配置 |
| `team:invites:create/list/revoke` | 创建一次性邀请、查看无 secret 元数据、撤销 |
| `team:join:preview/redeem` | 校验与预览、原子兑换长期设备凭据 |
| `team:members:list/change-role/revoke/leave` | 成员生命周期，全部主机鉴权与审计 |
| `team:commands:submit/status` | 权威命令、持久化幂等回执与冲突查询 |
| `team:assets:upload/download` | 经鉴权的知识/工件分块传输、hash 校验、取消与续传；不走 Yjs |
| `team:sync:subscribe` | 状态、游标、错误和 presence 订阅，不传输长期 secret |

新接口由 preload 白名单暴露，不开放通用 ipcRenderer。现有 `collab_space_members` 只有在字段语义、权限与生命周期审计通过后才可迁移复用，不能直接改名为真人邀请体系。

### 9.9 COL 验收

至少使用两个真实桌面实例，关键竞态使用三个实例：

- 正确邀请可加入；错误指纹、过期、已用、撤销、错误版本、错误空间均被拒绝且无敏感日志。
- 同一邀请并发兑换最多一个成功；同一 actor/space/payload 的 commandId 重发即使 baseVersion 已变化也返回原回执且只产生一次副作用；同 ID 不同 payload 被拒绝。
- viewer 的所有写操作即使手工构造消息也被主机拒绝；editor 不能管成员、审批或默认远程执行。
- 两人同时编辑文本可收敛；伪造权威投影 Yjs 更新、直接改看板同名字段均不能改变主机事实；并发状态迁移、删除与角色变更只接受权威结果。
- 审批竞态在同一主机两个窗口或重复命令下验证：只产生一个决策，重试拿原回执；editor/viewer 的远程审批请求均被拒绝。
- 主机离线时缓存可读、状态明确；editor 普通内容在当前角色未变时重连后合并且不重复，权威命令不自动重放；降级/撤销后的离线写队列不能自动合并。
- 知识/工件二进制上传下载经过逐资产鉴权、hash 校验、取消/续传；越权或撤销后不能继续传输，大文件不经过 Yjs。
- 撤销立即断开并阻止后续同步；UI 不承诺清除对方已有缓存。
- 主机换 IP、客户端重启、应用升级、schema 不兼容、队列损坏均有可恢复或明确停止路径。
- 仅共享指定空间，其他项目、完整账本、模型密钥和系统设置不可通过协作通道读取。

## 10. 订阅、套餐与商业化边界（条件项）

### 10.1 当前决定

【条件项】现有本地版没有账号、价格、支付、订阅或发票基础，也没有用户已确认的商业模式。因此当前只交付 Token 用量事实，不设计一个看似可用但没有真实交易与许可验证的“订阅页”。

未来若需要收费，优先评估**外部购买 + 签名离线许可文件**，而不是把中心账号、云同步或支付 SDK 偷渡进本地产品。价格、套餐、配额购买、退款、税务与发票必须由独立商业方案决定。

### 10.2 若未来启用离线许可，最低产品与前端规则

- 入口在 Settings → 许可，不与 Ledger 混为“账单”。
- 许可只含 licenseId、edition、entitlements、issuedAt、expiresAt、schemaVersion 和签名等必要信息；签名校验在主进程，公钥内置，私钥永不下发。
- 状态限定为 `unlicensed / active / expired / invalid`；是否设置 grace 必须由商业决策另行确认，不默认发明。
- 过期或无效时，本地项目、对话、知识、工件、流水始终可读取和导出；只能限制明确的付费新增能力，不能远程删除数据或锁死整个应用。
- 断网时可验证本地签名许可；界面显示真实验证结果，不伪造在线激活。系统时钟回拨、许可损坏、签名算法升级需要测试。
- 不设置远程 kill switch；不将邀请 token、文档或任务正文发送到许可服务。

SUB 的验收必须在商业模式和许可格式获批后单独立项，不能阻塞 P0/P1 的真实本地能力。

## 11. 本地可观测性：诊断与审计

### 11.1 入口与目标

【目标】在 Settings → 诊断与审计提供统一只读视图，关联现有 run/task/tool/approval/sandbox/audit 事实。它服务故障定位与责任追踪，不另造运行状态，不变成开发者专属日志洪水，也不新增一级导航。

### 11.2 页面与交互

- 运行列表：时间、项目、助手/角色、任务、状态、持续时间、Token（有真实关联时）；按状态/项目/时间/runId/taskId 筛选。
- 运行详情：按时间关联模型阶段、工具调用、审批决定、沙箱降级、重试、错误与工件；敏感参数默认折叠并脱敏。
- 失败归因：区分配配置、模型服务、工具、审批拒绝/超时、沙箱、用户取消、未知；证据不足时必须为 unknown，不能自动“甩锅”。
- 审计视图：邀请/成员/权限/导出/删除等事件，owner 可见；presence 不进入审计。
- 诊断导出：用户主动选择范围与路径，默认脱敏；导出前列出可能包含的数据类型。
- 日志保留与清理：展示本地占用、保留规则和清理影响；清理不能破坏仍被运行引用的必要审计事实。

### 11.3 目标读取契约

`diagnostics:runs:list`、`diagnostics:runs:detail`、`diagnostics:audit:list`、`diagnostics:export` 均需分页、schema 校验、项目/成员授权和统一错误码。详情通过 runId/taskId 关联现有记录，不要求前端拼接多个互相竞争的“成功”状态。

### 11.4 OBS 验收

- 一个失败运行能沿同一时间线看到真实工具、审批、沙箱与错误证据；无记录处明确缺口。
- API key、邀请 secret、成员 credential、safeStore 内容不会进入视图或导出。
- 普通 editor/viewer 不能读取其他空间或 owner 审计。
- 清理、导出、空数据、损坏日志、跨版本字段缺失均有可理解反馈。
- 诊断页面只读，不提供绕过审批的“重放危险命令”快捷入口。

## 12. 跨页面交互、组件与错误规范

### 12.1 组件使用

- 按钮使用既有 Button，Tab 使用 ui/TabBar，行内错误使用 InlineAlert；不要为新页面复制裸 button 和一套键盘逻辑。
- 图标必须有可读名称；仅图标按钮有 tooltip 与 aria-label。产品 UI 不使用 emoji 代替图标或状态。
- 弹窗有焦点圈定、Esc 关闭、关闭后焦点恢复；破坏性确认不能被 Enter 连续误触。
- 列表、表格和详情采用统一空/错/权限骨架；图表必须提供可访问的数据表或摘要。
- 大列表优先分页，确需虚拟化时保留键盘焦点、行高测量和读屏语义；不能为 51 个助手过度设计。

### 12.2 表单与操作反馈

- 用户输入、文件、邀请载荷、外部 API 响应都在系统边界校验；内部 canonical 状态不重复做无意义防御。
- 禁用按钮附近说明原因；能修复时给直接出口。错误摘要与字段错误关联，不只靠颜色。
- 成功 toast 只作补充；关键结果要在页面持久可见。危险操作结果以主进程回执为准。
- 删除、撤销、导出覆盖、离开脏草稿等确认文案写清对象和后果，不使用泛化“确定吗”。

### 12.3 统一错误语义

新 IPC 错误至少映射为稳定 code + i18n messageKey + retryable，详细技术信息只进脱敏诊断日志。

| code | UI 处理 |
|---|---|
| `INVALID_ARGUMENT` | 指向需修正的输入，不自动重试 |
| `UNAUTHORIZED` | 重新校验本地/成员凭据；不能循环登录弹窗 |
| `FORBIDDEN` | 显示权限边界，回安全页面 |
| `NOT_FOUND` | 资源已删除/不可见；不清空无关数据 |
| `CONFLICT` | 刷新权威状态，让用户重新确认；不用于已成功命令的同载荷重试 |
| `COMMAND_REUSE` | 同 commandId 不同 payload，拒绝并保留证据，不自动改写命令 |
| `PRESET_CHANGED` / `CONTEXT_PLAN_STALE` | 保留草稿，重新生成权限/知识预览并由用户确认 |
| `UNAVAILABLE` / `OFFLINE` | 保留缓存与草稿，按策略重试 |
| `VERSION_INCOMPATIBLE` | 停止同步，给升级/导出路径 |
| `CERT_FINGERPRINT_MISMATCH` | 立即断开，不提供绕过 |
| `INVITE_EXPIRED / INVITE_USED / INVITE_REVOKED` | 说明需新邀请，不重复消费 |
| `INDEX_UNAVAILABLE / SOURCE_NOT_READY` | 区分索引故障与仍在处理，可重试或等待 |
| `EXPORT_FAILED / CANCELLED` | 保留筛选，区分用户取消和真实失败 |

不得把原始 SQL、堆栈、完整路径、token 或密钥直接显示给普通用户。

## 13. 安全、隐私与数据生命周期

### 13.1 信任边界

1. Renderer 是不完全可信的展示层：主进程校验所有 IPC 参数、权限与资源范围，preload 只暴露窄接口。
2. 文档、网页、工具输出和协作者输入都是不可信内容：不能改变系统指令、审批、沙箱或安装策略。
3. LAN 不是天然安全网络：仍需要 WSS、指纹、一次性邀请、成员凭据、消息授权与限流。
4. 角色预设不是安全豁免：官方或内置助手同样经过 prompt/tools/approval/sandbox 校验。
5. 远程模型是外部边界：发送前明确任务和知识范围，密钥只在主进程，不进入 Renderer、协作文档或日志。

### 13.2 数据分类与最小披露

| 数据 | 默认位置 | 共享/发送规则 |
|---|---|---|
| 项目、任务、工件 | 本地 | LAN 仅共享指定空间；远程模型仅收到执行所需内容 |
| 知识源与 chunks | 本地应用存储 | 项目显式授权；空间显式共享；注入前预览 |
| Token 流水 | 本地 | 默认 owner；CSV 由用户主动导出 |
| API key/成员 credential/invite secret | safeStore 或仅哈希 | 不进 Renderer 日志、CRDT、CSV、埋点 |
| 诊断与审计 | 本地 | 主动脱敏导出；不默认上传遥测 |
| 本地产品指标 | 本地 | 默认不外发，只存事件元数据，不存正文 |

### 13.3 迁移、备份与删除

- 新表/新列采用可重复、带 schemaVersion 的事务迁移；迁移前备份，失败时不启动半可用功能。
- Ledger 不修改历史流水；知识索引可重建但原始 source 不随意重写；协作 CRDT schema 升级要协商版本。
- 回滚只停功能，不删除新数据。旧版本无法识别新 schema 时保持功能关闭，而不是强行读写。
- 用户可导出项目/知识/账本和必要协作内容；备份是否加密、包含哪些附件必须明示。
- 删除说明索引、历史引用、缓存和备份的不同边界，不夸大为“所有副本已彻底擦除”。

## 14. i18n、无障碍与性能预算

### 14.1 国际化

- 仅 zh-CN/en-US；所有新文案走 i18n key，无裸中文、无拼接语序、无硬编码复数。
- 路由 key、错误 code、CSV 字段、审计事件保持稳定的英文机器值；显示文案本地化。
- 日期时间使用用户时区和 Intl；账本查询边界统一转 UTC，CSV 明示时间格式。
- 助手或文档原始内容没有翻译时保留原文并说明，不静默机器翻译后冒充官方文案。
- 英文长文本、200% 文本缩放和窄窗口下不遮挡主要操作。

### 14.2 无障碍

- 目标 WCAG AA：对比度、可见焦点、语义标题、表单 label、错误关联、状态不仅靠颜色。
- Tab 支持方向键/Home/End；弹层焦点圈定与恢复；拖拽看板提供键盘“移动到…”替代操作。
- 加载、同步、索引进度用适当 live region，避免高频播报；支持 reduced-motion。
- 图表有文本摘要和数据表；Token 高低、同步在线/离线、成功/失败均不只靠红绿颜色。

### 14.3 性能目标不是当前实测结果

目前没有本方案对应的新能力性能基线，以下均为**验收预算**，实施时先在参考机器记录基线，再判断达标；不得把预算写成既有成绩。

| 场景与测试数据 | 验收预算 | 设计手段 |
|---|---|---|
| 任意一级导航/Tab | 100ms 内有视觉反馈；不出现双高亮 | 单一路由状态、活动 Tab 挂载、取消旧请求 |
| 51 个助手搜索筛选 | 本地交互 p95 ≤100ms | 目录缓存、按选中项取 runtime、不无界 N+1 |
| 100,000 条 Token 流水 | 每页默认 100；查询 p95 ≤1s（参考机器记录配置）；不全量装入 Renderer | keyset 分页、必要索引、读快照、流式导出 |
| 10,000 个知识 chunks | 已就绪检索 p95 ≤500ms；索引时无不必要的 UI 长任务 | FTS5、后台解析、限制 snippet 与上下文预算 |
| 2–8 客户端、1,000 张看板卡片 | 正常 LAN 在线更新 p95 ≤1s；断线可恢复且无重复权威副作用 | 增量 Yjs、批量消息、命令幂等、限流 |
| 大型诊断/CSV 导出 | 可取消、有进度、不阻塞其他页面 | 主进程分批处理、背压、临时文件清理 |

若验证表明预算不适合参考硬件，必须在实施前用数据调整并记录原因，而不是删除性能测试。

## 15. 产品指标与本地事件

### 15.1 指标原则

- 当前没有新业务漏斗基线，所有基线标记为“待建立”；不编造提升百分比。
- 指标用于判断闭环是否可用，不用点击量替代任务质量。
- 默认只记录本地匿名事件元数据：事件名、时间、结果码、耗时、无内容计数；不记录任务正文、文档内容、密钥、邀请链接或可识别成员信息。
- 数据正确性和安全类指标是门槛，不用平均值掩盖错误。

### 15.2 指标体系

| 层 | 指标 | 定义/限制 |
|---|---|---|
| 核心结果 | 有效完成任务数 | canonical run 成功且结果可查看；不等同于 IPC 调用次数 |
| 助手漏斗 | 目录详情→草稿→提交→成功→查看工件 | 各步用匿名 run/draft 关联；无工件任务不强算最后一步 |
| 助手可发现性 | 搜索无结果率、needs-setup 率、角色预设失败率 | 用于修数据/配置，不自动评价助手好坏 |
| Studio | 项目上下文错误数、看板迁移冲突率、工件打开失败率 | 上下文错误目标为 0 |
| Ledger | 明细/汇总/CSV 对账一致率、导出失败率 | 同过滤器/asOf 一致率必须 100% |
| KB | 导入成功率、无命中率、显式注入率、引用可回链率 | 无命中不直接等于质量差；禁止虚构引用 |
| COL | 邀请成功率、同步恢复成功率、命令冲突/重复率、撤销生效失败数 | 重复权威副作用与越权目标为 0 |
| 可靠性 | run 成功率、失败分类、重试恢复率 | 用户取消与系统失败分开 |
| 性能 | 第 14 章各 p95 | 发布时记录设备、数据集和版本 |

建议本地事件：`assistant_catalog_loaded`、`assistant_task_submitted`、`studio_project_changed`、`ledger_export_finished`、`knowledge_import_finished`、`knowledge_context_injected`、`team_invite_redeemed`、`team_sync_recovered`、`diagnostics_exported`。事件只存结果和必要 ID 的匿名映射，不存敏感参数。

## 16. 测试策略与总体验收

### 16.1 测试层级

| 层级 | 必测内容 |

| 纯函数/单元 | 路由互斥、筛选规范化、日期区间、keyset cursor、CSV 转义、角色矩阵、邀请状态、命令 reducer、错误映射 |

| 单主机双窗口端到端 | owner 对同一审批的两个窗口/重复命令只产生一个决策，重试返回原回执 |
| 多实例端到端（M4 起） | 两/三客户端加入/协作/撤销/重连，以及 editor/viewer 远程审批均被拒绝；不假设存在多个 owner 客户端 |
| 安全 | 构造越权 IPC/WS、SQL/路径/HTML/公式注入、恶意文档提示注入、日志与导出泄露 |

### 16.2 跨能力关键用例

每条标注适用里程碑；当前里程碑只执行已具备能力的子集，后续里程碑必须补跑对应回归，而不是让 M2/M3 反向依赖 M4。

1. **单一项目闭环（M1 做项目/助手子集，M2 加账本，M3 加知识）**：在项目 A 选助手并引用 A 的知识，运行、工件、看板、Token 流水都关联 A；切到 B 后任何旧响应不能写入 A/B 的错误视图。
2. **无数据闭环（每个里程碑）**：全新工作区的助手目录若真实为空、账本 0、知识 0、协作未开启，各自显示正确空态，无示例假数据。
3. **权限闭环（M2/M3 做本机项目子集，M4 做完整 LAN）**：viewer 获取 sourceId/taskId/commandId 后手工构造请求，主进程仍拒绝；撤销后已有连接也失效。
4. **提示注入闭环（M3，M4 加访客）**：知识文档要求执行危险命令或泄露密钥时，仍按系统策略审批/拒绝，文档文本不获得指令权。
5. **并发闭环（M2 做导出，M4 做邀请/状态，owner 审批在单主机双窗口测试）**：同一邀请、审批、任务状态和导出请求并发执行，不产生重复副作用或双成功。
6. **离线闭环（M4）**：主机离线、重连、版本不兼容、缓存存在时，内容不丢、状态不伪报、权威命令不自动重放。
7. **迁移回滚闭环（每个涉及迁移的里程碑）**：旧版本数据升级后可读，新功能回滚只关闭入口；数据不删除、旧版本不错误解析新 schema。
8. **隐私闭环（每个涉及模型、共享或导出的里程碑）**：远程模型发送范围可预览；日志、CSV、诊断导出和本地事件不含 secret/credential/API key。

### 16.3 每个里程碑的完成定义（DoD）

只有同时满足以下条件才可标记完成：

- 真实数据链路贯通，目标页面不是静态壳；
- 本章对应验收及**当前里程碑适用**的跨能力用例通过，有实际输出证据；后续里程碑新增权限/同步面时补跑其新增子集与前序回归；
- 主进程授权、审计、错误和空态完整；
- zh-CN/en-US、键盘、读屏与减少动态效果通过；
- 性能在声明的数据集与参考环境测量，结果不冒充其他环境；
- 数据库迁移、feature flag、回滚和旧入口兼容已验证；
- 文档中的【目标】经发布后单独更新为已验证现状，不能由开发者口头勾选。

### 17.2 发布策略

- 新数据读取与知识能力使用独立 feature flag，默认关闭直至对应验收完成；IA 迁移可用内部开关，但同一会话只能呈现一套入口。
- 继续遵守现有 collab 默认关闭原则；即使 M4 开发完成，也需在发布说明中明确 LAN 适用范围，不能宣传成公网协作。
- 发布包包含 schema 迁移、双语资源、权限/安全测试、性能结果和回滚说明。
- 灰度顺序：单人新工作区 → 单人已有数据迁移 → 两客户端 LAN → 多客户端与断网恢复。每一步通过再扩大。
- 不在发布说明中使用“零成本”“完全离线推理”“绝对安全”“彻底删除”等超出证据的措辞。

### 17.3 回滚触发与动作

| 触发 | 立即动作 | 数据原则 |
|---|---|---|
| Ledger 明细/汇总/CSV 不一致 | 关闭 Ledger 新入口，保留 quota 与 Desk 摘要 | 不修改流水；保留查询日志供定位 |
| KB 越权、错误引用或索引损坏 | 停止知识注入，必要时关闭 KB | 保留 sources 供重建索引；不假装原引用正确 |
| 协作越权、重复审批/执行、证书校验问题 | 停止 host、关闭 collab、撤销相关邀请 | 客户端进入缓存只读；保留权威审计 |
| 导航迁移导致能力不可达/双入口 | 回退到旧 IA 适配器 | 不删除新路由数据或草稿 |
| 迁移失败或性能严重退化 | 阻止启动新功能并回到旧只读路径；只有“迁移尚未产生任何新写入”时才可恢复迁移前备份 | 已发布后的回滚只关闭功能并保留当前数据库，提供兼容只读/导出；不删表、清空队列或用旧备份覆盖新事实 |

回滚后的升级必须重新跑对应里程碑验收，不能只把 flag 再打开。

## 18. 风险、替代方案与决策记录

### 18.1 风险登记

| 风险 | 早期信号 | 缓解/退出 |
|---|---|---|
| 旧 IA 门禁与新归属冲突 | 双高亮、旧测试失败、两个 Teams 实例 | 显式更新语义判据与组合覆盖；旧链接只重定向 |
| Studio 使用 default 串项目 | 切项目后资产不变、跨项目数据出现 | 强制 projectId，无项目空态，取消旧请求 |
| quota 字段被误解释 | member/模型/成本维度看似合理但无证据 | M0 数据字典；capabilities 隐藏未证实维度 |
| 大流水查询/导出阻塞 | UI 卡顿、内存增长、分页重复 | keyset、索引、分批、asOf、取消与性能数据集 |

| 文档提示注入 | 文档要求忽略规则/调用工具 | 不可信上下文隔离、权限不继承、攻击用例 |
| LAN 被误当可信网络 | 明文连接、通用文档读写、无撤销 | WSS+指纹+一次性邀请+逐消息授权，失败即关闭 |
| 纯 CRDT 破坏业务一致性 | 双审批、非法任务状态、角色并发覆盖 | 主机权威命令、版本、幂等与审计 |

| 订阅侵蚀本地可用性 | 过期无法读自己的数据 | 商业门禁明确禁止；许可只控制付费新增能力 |
| 指标变成隐蔽遥测 | 事件含正文/链接/成员信息 | 本地最小事件、字段审查、默认不外发 |

### 18.4 不再悬置的产品问题与仅剩实施验证

知识库入口、Ledger 命名、编制归属、协作拓扑、角色、主机离线行为、远程执行默认值均已在本文决定，不再以“待定”阻塞设计。

仍需工程验证的事项只有：现有数据库完整字段与单位、目录/runtime ID 映射、FTS5 构建与中文召回、collab authMiddleware/WebSocket 覆盖、历史数据迁移与参考硬件性能。这些验证可能改变实现方式或字段可用性，但不能被用来降低权限、真实性和本地数据可退出原则。

## 20. 最终交付检查清单

### 产品与 IA

- [ ] 每个新增能力都有用户任务、唯一入口、非目标和完整异常路径。
- [ ] Assistant=选助手/派活，Studio=项目与 AI 资产，Settings 团队=真人协作，Ecosystem=扩展。
- [ ] Ledger 不承担金额；Desk 摘要与 Ledger 明细不混口径。
- [ ] 不存在编制、看板、知识或账本的双主入口。

### 前端逻辑

- [ ] 页面、覆盖层、Tab、项目、筛选和草稿状态定义一致，旧请求不会覆盖新上下文。
- [ ] 所有列表和表单具备加载、空、筛选无结果、错误、权限、离线和重试状态。
- [ ] 防重复提交、权威状态回执、冲突刷新、焦点恢复、键盘替代操作完整。
- [ ] 仅 zh-CN/en-US，无 UI emoji、无裸文案、无虚构翻译。

### 数据、安全与隐私

- [ ] 真实目录、Token 流水、知识 chunks、协作成员都有明确真源与生命周期。
- [ ] Renderer 不持有密钥/长期 credential，不直接读数据库或任意文件。
- [ ] 项目、空间、成员与角色在每个主进程入口重新鉴权。
- [ ] 知识/协作文档不改变系统指令和审批；远程模型发送范围可见。
- [ ] 日志、指标、CSV 和诊断导出不含 invite secret、credential、API key。

### 验收与发布

- [ ] 每里程碑有真实数据、集成、多实例（适用时）、安全和非功能证据。
- [ ] 性能结果附设备、数据集和版本；没有基线的业务指标明确待建立。
- [ ] feature flag、迁移、旧入口、回滚和数据保留都经过验证。
- [ ] 未实施的能力仍标记【目标】，发布后才依据证据更新现状。
