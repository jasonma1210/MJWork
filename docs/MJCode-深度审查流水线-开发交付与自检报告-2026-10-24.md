## 2. T-01 冻结与基线

**分类/证法**：`baseline`（不属于 A/B/C/D；不产出任何红绿结论）

**原始素材输入**：`git rev-parse HEAD`、`git status --porcelain=v1`、`desktop/package.json` 的 test 脚本、干净检出后的 `npm test` 原生 stdout。

**工具与命令**
```bash
git worktree add --detach --force /tmp/mjrp-wt-<SHA> <SHA>
ln -s <repo>/node_modules <wt>/node_modules      # 仓库根
ln -s <repo>/desktop/node_modules <wt>/desktop/node_modules
cd <wt>/desktop && NODE_OPTIONS=--preserve-symlinks npm test
```
`NODE_OPTIONS=--preserve-symlinks` 是必需项：缺它时 electron 打桩因 Node 解析真实路径而失效，会报 `ipcMain undefined` 假红。

**实现要点**
1. 先 `assert_proof_binding T-01 baseline`；2. `assert_full_sha`（40 位且 `cat-file -e` 存在）；3. `gate_clean_worktree`；
4. 建 worktree + 依赖软链；5. 跑套件，`grep` 汇总行 `总计 N · 通过 N · 失败 N · 跳过 N`；
6. `quad_verify`（不闭合 ⇒ 退出码 6）；7. 写 `T-01.baseline.md` + JSON 记录。

**机器验收判据**
- 记录含完整 SHA、命令原文、`exit_code`、四元组、`dir_entry_counts`；
- `总 = 过 + 败 + 跳` 成立；
- 同一命令连跑两次四元组一致（`--double`）；
- 拒绝分支下**不得**产出 `T-01.baseline.md`。

**失败分支**

| 退出码 | 触发 | 处置 |
|---|---|---|
| 3 | 工作区 dirty | 读数作废；提交或清理后重跑；不得用工作区读数替代 |
| 5 | SHA 非 40 位 / 不存在 | 修正 `--sha` |
| 6 | 四元组不闭合 | 判为「汇总公式坏了」，不是被测代码坏了 |
| 7 | 日志中无汇总行 / worktree 建失败 | 见 `out/T-01.worktree.log`、`out/T-01.test.log` |

**样例输出（真实）**
```

 M .wiki-creator/wiki/.manifest.json
 ?? deliverables/
 ...（共 9 项）
exit=3
```
夹具（合成干净仓库，`MJRP_TEST_CMD='bash fake-test.sh'`）：
```

```

## 3. T-02 源码形态断言普查

**分类/证法**：`census`（不做「是否假闸」判定；只产出候选池）

**原始素材输入**：`desktop/test/*.test.{js,mjs}`（现算 286 个文件）。**不读任何台账或历史报告。**

**工具**：`rg`（定位）+ Node（别名识别与括号配平）。不用 ast-grep，因为需要的是「断言块内是否引用源码读取别名」这一层数据流，ast-grep 表达成本更高且收益不明显。

**实现要点（两道结构筛）**
1. 别名识别：`const X = (...) => fs.readFileSync(...) | stripComments(...)`；
2. 断言块配平：从 `check(`/`assert.ok(` 起按括号深度跨行拼接（上限 12 行）；
3. 筛①文本匹配语义：块内出现 `.includes/.match/.test/indexOf/.startsWith/.endsWith`；
4. 筛②路径指向产品树：块内字符串字面量命中 `main|agent-core|renderer/src|preload|scripts`；
5. 别名命中 **或** （行内 `readFileSync` + 产品路径）且通过筛① ⇒ 记一条候选。

> 两道筛的必要性有实测支撑：未加筛②前，`apply-patch-hardening.test.js` 的「校验 patch 后文件内容」被误收为源码断言（它读的是**运行期产物**），误收率一度使池从 139 条虚增到 256 条。

**机器验收判据**
- 每条记录含绝对路径 + 数字行号（`awk` 校验，不合格即退出码 7）；
- `verdict` 固定 `CANDIDATE_PENDING`，脚本**不得**自行输出「假闸」；
- 候选数为 0 ⇒ 必须 FAILED（空池不能当作「无假闸」的证据）。

**失败分支**：空池 ⇒ 7；记录缺路径/行号 ⇒ 7；被读目录有未提交改动 ⇒ 3（局部干净口径，见 §5）。

**样例输出（真实）**
```
[T-02] files=286 records=139（全部 CANDIDATE_PENDING）
bad=0
| 2 | `/…/desktop/test/apply-patch-hardening.test.js:71` | (inline) | stripComments=N | 16 | `'a.js'` | … |
```
> 已知池内包含 `memory-file-channel`（2 条），该套件在上一轮已被实测为「会被杀死」，最终裁决列填 `NOT_FAKE(已实测)` 而非自动判定。

## 4. T-07-1 docx 表格框线（最小闭环验证单元）

**分类/证法**：条目 `P0-8` = **B 类**（已实现、语义错误）⇒ 合法证法 `counterfactual`（接通/修复前后两次实测；C 类红线不适用）

**原始素材输入**：`desktop/main/docTools.js`（生产渲染路径）、`desktop/node_modules/docx` 的产物、`word/document.xml` 原始 XML。**不读审计结论作为依据**——审计只作为「待验证命题」。

**工具与命令**
```bash
node review-pipeline/T07_1_docx_borders/probe_docx_table.js
# 内部：require(main/docTools.js) → initDocTools(桩依赖) → toolDocCreate → unzip -p <docx> word/document.xml
bash review-pipeline/T07_1_docx_borders/run_counterfactual.sh
```

**判据（二值，机器可判）**：读 `<w:tblBorders>` 下 `top/left/bottom/right` 四边，`w:val ∉ {none,nil}` 的条数 == 4 ⇒ `BORDERS_PRESENT`，否则 `NO_FULL_BORDERS`。
**为什么不只看节点存在**：docx 会写 `<w:tblBorders>` 节点但可全为 `w:val="none"`，只看节点存在会把「全 none」判成有框线（假绿）。该反例已由注入实验实证。

**双分支设计（关键）**
- 分支①：基线 `NO_FULL_BORDERS` ⇒ 注入 `single` ⇒ 必须 `BORDERS_PRESENT`（反事实成立，条目 CONFIRMED）；
- 分支②：基线 `BORDERS_PRESENT` ⇒ 注入 `none` ⇒ 必须 `NO_FULL_BORDERS`（**证明探针不是假绿**）⇒ 条目 EXCLUDED。

**实测结果（本机，SHA `08b874f…`）**

| 步骤 | verdict | 关键读数 |
|---|---|---|
| 1 基线（生产路径） | `BORDERS_PRESENT` | `edges` 六边全 `single`；`visible_outer_edges=4`；`table_count=1`；`bytes=9824`；`tblBorders_node=true` |
| 2 注入 `none` | `NO_FULL_BORDERS` | 六边全 `none`；`visible_outer_edges=0`（探针灵敏度成立） |
| 3 还原后复探 | `BORDERS_PRESENT` | 与基线一致；`git diff --numstat desktop/main/docTools.js` ⇒ **0 行** |

**条目结论：`P0-8 = EXCLUDED`（审计结论未复现）**

证据链：
1. `docx` 依赖版本 **9.12.0**（`node_modules/docx/package.json`）；
2. `rg -n 'tblBorders|borders' desktop/main/docTools.js` ⇒ **0 命中**（源码确实没显式设边框）；
3. 但库对 `Table` 的默认行为是写 6 条 `single` 边框 ⇒ 审计「库默认 `TableNormal` ⇒ Word 里无框线」的推断不成立；
4. 探针能识别「无框线」（步骤 2），故步骤 1 的 `BORDERS_PRESENT` 不是假绿。

> 这条结论本身就是流水线的样本价值：**审计结论是命题，不是事实；只有跑出产物才能判真伪。**

**失败分支**

| 退出码 | 触发 | 处置 |
|---|---|---|
| 3 | 变异目标 `docTools.js` 已 dirty | 先还原该文件（变异安全口径） |
| 7 | 锚点不唯一 / 探针报 `PROBE_ERROR` / 注入后未达期望 verdict | 判为「无效实验」，不得改期望值凑绿 |
| 8 | 还原后 verdict 与基线不一致，或 `git status -- target` 非空 | 立即停止，人工核对 diff |
