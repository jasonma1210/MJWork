## 一、修复明细

### P0-1 网络设置关闭静默丢配置
- **根因**：搜索提供方与流式超时均为「本地草稿 + 手动保存」，但设置弹层关闭（Esc / X / 遮罩）无任何拦截，未保存配置静默丢失，用户会判定整块功能不可用。
- **修复**：
  - `NetworkTab.tsx`：新增 `providersDirty`（搜索提供方）与 `streamDirty`（流式超时）双脏标记，分别由 `update()` / `StreamTimeoutSection` 的 onChange 置位、`save()` 成功后清除；综合后通过 `onDirtyChange` 上报。
  - `SettingsModal.jsx`：持有 `networkDirty`，关闭入口统一收口到 `handleClose()`：有脏标记则 `confirm` 二次确认（确认=丢弃并关闭，危险态；取消=留下去保存），否则直接关闭。
  - 新增 i18n 键 `settings.unsavedNetworkTitle` / `unsavedNetworkMsg` / `discardClose`（zh-CN + en-US）。
- **边界**：仅在 network 页内改动后直接关窗时拦截；切到别的设置 tab 再关窗属边角（草稿丢失留待后续批次，不在 P0-1 范围）。

### P1-1 切会话输入框草稿残留
- **根因**：切会话 effect 清了 `attachments`/`queued`/`lastFailed`，却漏掉 `input`，A 会话写了一半的需求会残留在 B 会话输入框、回车误发。
- **修复**：`ChatArea.jsx` 在 `if (!isCreatingThread)` 分支补充 `setInput('')`；新建会话（undefined→id）保持不清。

### P1-2 右栏 tab 切走卸载丢状态
- **根因**：除 artifact 外，diff/files/subtasks/terminal/browser/sidechat 均为条件渲染，切 tab 即卸载，终端命令、浏览器页面、diff 行内评论草稿、侧聊上下文全部清空。
- **修复**：`RightPane.jsx` 七个面板统一改为 hidden 常驻保活（激活时 `contents`、非激活时 `hidden`），与 artifact 既有语义一致。代价：7 个面板常驻挂载，遵循本文件「保持上下文」设计意图（与 artifact 同策略）。

### P1-10 选中编制视觉像派活（实为普通对话）
- **根因**：选中编制后目标条（IconUsers + 本次编制 + 团队名 + 成员 + 预算）与发送按钮（人群图标）视觉像已派活，但 `sendOrDispatch` 实际走 `send()` 普通对话，roster 仅作 `candidateRoster` 会话上下文（`ChatArea.jsx:350`）。代码注释明确这是有意设计（编制是偏好，派活是显式动作）。
- **修复**：不改业务路由；在目标条下方加一行常驻澄清「团队作为本轮对话上下文参与，发送仍是普通对话；要立即派活执行，请用「+ → 军团」中的「立即派活」」。发送按钮 tooltip 已通过 `composer.dispatchTip` 澄清（此前已有）。
- **新增键**：`composer.rosterContextHint`（zh-CN + en-US）。

### P1-11 连接器「启用」≠「已连接」
- **根因**：连接器卡片主视觉是启用开关（仅控制 + 菜单可见性），缺连接状态，用户开开关以为接好了，派单时工具调不通。
- **修复**：`EcosystemModal.jsx` 在开关下方加一行澄清「启用仅将其加入 + 菜单；配置凭证并在会话中连接后，其工具才可被调用」。业务逻辑不变。
- **新增键**：`ecosystem.enableOnlyMenuHint`（zh-CN + en-US）。
